# 操作系统面试复习总结

> 大厂实习生面试难度，20 题问答整理

---

## 1. 进程和线程的区别

- **进程**：OS 分配资源的最小单位
- **线程**：CPU 调度和执行的最小单位，属于进程
- 同一进程内的线程**共享堆、代码段、全局变量**，但各自有独立的**栈和寄存器**
- 进程切换开销 > 线程切换开销（进程切换要切页表）

---

## 2. 死锁的四个必要条件

1. **互斥条件**：资源同一时刻只能被一个进程占用
2. **请求与保持**：进程已占有资源，同时申请新资源
3. **不可剥夺**：已分配的资源不能被强行抢占
4. **循环等待**：多个进程形成环形等待资源链

---

## 3. 进程间通信（IPC）方式

- **管道**：匿名管道（有亲缘关系进程用）、命名管道 FIFO
- **信号量**
- **信号**
- **共享内存**
- **消息队列**（内核维护的消息链表，格式化、可异步）
- **Socket**（可本机也可跨网络）

---

## 4. 虚拟内存

每个进程看到独立的虚拟地址空间，通过**页表**映射到物理内存。

**解决的问题：**
1. **隔离**：进程间内存隔离，无法互相读写，提升安全性和稳定性
2. **突破物理内存限制**：不常用页面可换出到磁盘（swap），使用比物理内存更大的地址空间
3. **简化内存管理**：进程看到连续地址空间，不用关心物理内存碎片

---

## 5. 页面置换算法

- **FIFO**：淘汰最早进入内存的页
- **LRU**（最近最少使用）：淘汰最久未使用的页
  - **实现**：`HashMap + 双向链表`，HashMap 保证 O(1) 查找，链表维护访问顺序（头=最近用，尾=最久未用），Java 的 `LinkedHashMap` 就是这个结构
- **OPT**（最优）：淘汰未来最长时间不会用到的页，理论最优、无法实现

---

## 6. 用户态 vs 内核态

- **内核态**：可执行特权指令（I/O、修改页表、关中断），访问所有内存和硬件
- **用户态**：只能执行普通指令，访问用户空间内存
- **切换方式**：系统调用（syscall）、中断、异常
- **意义**：安全（防止用户程序破坏硬件/其他进程）+ 稳定性（用户程序崩溃不影响内核）

---

## 7. 系统调用 —— `read()` 完整流程

1. 用户程序调用 `read()`（libc 库函数）
2. 库函数把系统调用号和参数放入寄存器，执行 `syscall` 指令
3. CPU 切换到内核态，跳转到系统调用入口
4. 内核找到 `sys_read`，检查文件描述符权限
5. 查**页缓存（page cache）**：
   - 命中 → 直接从内核空间复制到用户缓冲区
   - 未命中 → 触发磁盘 I/O，等待数据载入缓存，再复制
6. 切回用户态，返回读取字节数

关键词：**系统调用号、内核态切换、page cache、内核→用户空间拷贝**

---

## 8. 上下文切换（Context Switch）

保存/恢复的内容：
- 程序计数器（PC）、栈指针（SP）
- 通用寄存器（RAX、RBX...）
- CPU 状态标志位
- 均保存在进程的 **PCB（进程控制块）**

**进程切换 vs 线程切换**：进程切换要**切换页表、刷新 TLB**，开销远大于线程切换（线程切换只需保存寄存器和栈）。

---

## 9. TLB（快表）

CPU 内部缓存虚拟地址→物理地址的映射，避免每次访问都要查内存里的页表。
- **命中**：一次内存访问
- **未命中**：先查页表（额外内存访问），再访问目标地址
- 进程切换时需要**刷新 TLB**（新进程地址映射完全不同）

---

## 10. 分页 vs 分段

| | 分页 | 分段 |
|--|--|--|
| 划分方式 | 固定大小，OS 管理 | 按逻辑单元（代码/数据/堆/栈），大小可变 |
| 优点 | 无外部碎片，内存利用率高 | 有语义，便于保护和共享 |
| 缺点 | 有内部碎片 | 有外部碎片 |

现代 OS（如 x86）用**段页式**：先分段再分页，兼顾语义和利用率。

口诀：**分页解决碎片，分段提供语义**

---

## 11. 内存抖动（Thrashing）

系统进程太多，物理内存不够，OS 不停做页面换入换出，CPU 大部分时间处理缺页中断，几乎不执行用户程序。

本质：**工作集总大小 > 物理内存大小**

**解决方法：**
1. 减少并发进程数
2. 工作集模型（保证工作集能全部留在内存里）
3. 增加物理内存（治本）
4. 优化页面置换算法（治标）

---

## 12. 僵尸进程 vs 孤儿进程

- **僵尸进程**：子进程已退出，父进程未调用 `wait()` 读取退出状态，PCB 仍占用资源 → 有害
- **孤儿进程**：父进程先退出，子进程被 **init 进程（PID=1）**接管 → 无害

**避免僵尸进程的方法：**
1. 父进程主动调用 `wait()`/`waitpid()`
2. 注册 `SIGCHLD` 信号处理函数，在里面调用 `wait()`（不阻塞）
3. 两次 fork：孙进程变孤儿，交给 init 处理

---

## 13. 死锁的预防 / 避免 / 检测与恢复

| 策略 | 做法 | 特点 |
|--|--|--|
| **预防** | 破坏四个必要条件之一（如资源编号、一次性申请全部资源） | 事前，粗暴，资源利用率低 |
| **避免** | 分配前预判是否导致不安全状态，不安全就拒绝分配 | 事前，精细。**银行家算法**属于此类 |
| **检测** | 定期扫描资源分配图，检测环路 | 事后 |
| **恢复** | 检测到死锁后，终止进程或剥夺资源 | 事后 |

---

## 14. 进程调度算法

| 算法 | 特点 | 适用场景 |
|--|--|--|
| FCFS 先来先服务 | 按到达顺序，有护航效应 | 简单场景 |
| SJF 短作业优先 | 优先跑最短任务 | 批处理系统 |
| 时间片轮转（RR） | 轮流执行时间片 | 交互式系统 |
| 优先级调度 | 高优先级先跑，可能饿死低优先级 | 实时系统 |
| HRRN 最高响应比优先 | `(等待时间+执行时间)/执行时间`，防止饿死 | 批处理系统 |
| **多级反馈队列** | 多队列+动态调整优先级 | **现代 OS 主流思想** |

**多级反馈队列细节：**
- 多个队列，优先级从高到低，时间片从小到大
- 新进程进最高优先级队列；时间片用完没跑完就**降级**
- 低优先级队列只有高优先级队列全空才能运行
- 等太久会**提升优先级**，防止饿死
- 短任务响应快，长任务减少切换开销，I/O 密集型任务优先级会被提升
- Linux 实际用的是 **CFS（完全公平调度器）**，思想不同（基于虚拟运行时间），但 MLFQ 是理解调度的基础

---

## 15. 缺页中断处理流程

1. CPU 访问虚拟地址，查页表发现页表项无效（present 位为 0）
2. 触发缺页中断，切换到内核态
3. 检查虚拟地址是否合法：
   - 不合法 → `SIGSEGV`（段错误）
   - 合法 → 继续
4. 找空闲页框：没有则用页面置换算法淘汰一页（脏页要先写回磁盘）
5. 从磁盘载入所需页面到物理内存
6. 更新页表映射
7. 切回用户态，**重新执行**刚才出错的指令

---

## 16. malloc 实现 & brk / mmap

**向 OS 申请虚拟内存的两种方式：**
- **`brk()`**：移动堆边界，申请连续内存，适合小块（<128KB）
- **`mmap()`**：在堆栈之间映射内存，不一定连续，适合大块（>=128KB），用完可 `munmap`

**malloc（glibc 实现叫 ptmalloc）做的事：**
1. 首次调用时向 OS 批量申请一大块内存
2. 用**空闲链表**按大小分类管理
3. `malloc(n)` → 从合适链表取出
4. `free()` → 还回链表，**不一定马上还给 OS**
5. 相邻空闲块自动合并，减少碎片

口诀：**小块用 brk 扩堆，大块用 mmap 映射；malloc 是内存池，free 不等于还给 OS**

---

## 17. inode 与文件系统

- **inode**：存文件元数据（大小、权限、时间、数据块位置），**不存文件名**
- **目录项（dentry）**：存文件名 → inode 号的映射
- 查找路径：`文件名 → 目录项 → inode号 → inode → 数据块`

**硬链接 vs 软链接**

| | 硬链接 | 软链接 |
|--|--|--|
| 本质 | 指向同一 inode | 存目标路径字符串 |
| 删源文件 | 文件还在（引用计数） | 链接失效 |
| 跨文件系统 | 不支持 | 支持 |
| 链接目录 | 不支持 | 支持 |

inode 数量格式化时固定，耗尽后即使磁盘有空间也无法创建新文件。

---

## 18. 同步/异步 与 阻塞/非阻塞

两个**正交**维度，不是固定搭配：

- **同步 vs 异步**：结果**如何通知你**（自己等/查 vs 系统回调通知）
- **阻塞 vs 非阻塞**：等待期间**能不能干别的**（挂起 vs 立刻返回可以去做别的事）

| | 阻塞 | 非阻塞 |
|--|--|--|
| 同步 | 同步阻塞：`read()`等数据来了才返回 | 同步非阻塞：立刻返回，自己轮询 |
| 异步 | 少见 | 异步非阻塞：性能最好，Node.js/Nginx 模型 |

---

## 19. I/O 多路复用：select / poll / epoll

一个线程处理多个连接的核心机制。

| | select | poll | epoll |
|--|--|--|--|
| fd 上限 | 1024（bitmap） | 无限制（动态数组/链表） | 无限制 |
| 拷贝开销 | 每次调用都拷贝 | 每次调用都拷贝 | 只在注册时拷贝 |
| 查找就绪fd | 内核+用户态都要 O(n) 遍历 | 同上，O(n) 遍历 | O(1)，事件驱动回调 |
| 数据结构 | bitmap | 动态数组/链表 | 红黑树（管理fd）+ 就绪链表 |

**epoll 核心：** 用红黑树管理注册的 fd，内核维护一个就绪链表，fd 就绪时通过**回调函数**加入链表，`epoll_wait` 只需要看链表，不用遍历全部 fd。

**epoll 两种触发模式：**
- **LT（水平触发，默认）**：只要 fd 还有数据，每次 `epoll_wait` 都通知
- **ET（边缘触发）**：只在状态变化时通知一次，必须一次读完，否则不再提醒。性能更高但编程复杂，**Nginx 使用 ET**

---

## 20. CPU 缓存一致性：MESI 协议

多核 CPU 各有自己的 L1/L2 缓存，同一内存数据可能被多核缓存，需要一致性协议避免脏读。

**四个状态：**

| 状态 | 含义 |
|--|--|
| **M**odified | 我改过了，与内存不一致，其他核没有这行 |
| **E**xclusive | 只有我有，与内存一致，没人改过 |
| **S**hared | 多核都有，与内存一致，都没改 |
| **I**nvalid | 已失效，不能用 |

**流程：** A 核要修改数据 → 广播通知其他核 → 其他核把该行标记为 **I** → A 核状态改为 **M**，直接在缓存里改 → 写回内存时才更新主存

**延伸**：Java 的 `volatile` 就利用这个机制，强制写操作让其他核缓存失效，保证可见性。

---

## 21. 中断：硬中断 vs 软中断

- **硬中断**：由硬件触发（键盘、网卡、磁盘、定时器），CPU 立刻停下处理，处理程序必须**短而快**
- **软中断**：由**内核**触发，用来处理硬中断"来不及做"的耗时后半段（如网络包的协议栈解析），可被硬中断打断

| | 硬中断 | 软中断 |
|--|--|--|
| 触发者 | 硬件 | 内核 |
| 时机 | 立即 | 硬中断结束后延迟执行 |
| 典型场景 | 键盘、网卡、定时器 | 网络包处理、任务调度 |

口诀：**硬中断处理紧急事，软中断处理后续事**
