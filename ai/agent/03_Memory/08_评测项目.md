记忆系统的价值 不在于存了多少 而在于 是否准确记住 正确召回 最后提升任务效果。
则评测分为三级：
- 写得对不对
- 找得准不准
- 最终有没有帮助

## 写入评测

先构建人工标注数据集  用户的消息+那些消息应该写入+记忆类型+预期的操作（增删改查）

去计算
- write precision ： 正确写入数量/实际写入数量 如果比较低 说明乱记 或者过度记忆
- write recall 正确写入数量/应该写入数量 比较低 说明 重要信息被漏掉

并且要关注 安全指标 对应硬约束力
- 敏感信息写入率
- 越权写入率

还可以关注
- 错误事实写入率
- 重复写入率

## 评测检索


**Recall@K**

前k条结果里 的召回率  用于判断是否漏召回

**Precision@K**

前k条结果里 有多少相关的 用于判断噪声是否过多

**MRR**

第一条正确记忆出现的越靠前 分数越高 适合评测重排效果

## E2E评测

写入和检索还不够 记忆被注入后 llm可能忽略 误用 or 过度使用。

所以需要比较 无memory vs 用memory

重点指标：
- 任务完成率
- 用户偏好遵循率
- 最新事实使用率
- 历史经验复用率
- 回答矛盾律
- token增量
- 平均延迟

## 评测集设计

不能只有正常情况  应该覆盖

- 明确稳定偏好： 是否写进long-tern memory
- 一次性要求：是否拒绝长期写入
- 用户纠正旧偏好 是否使用新事实
- 不同项目不同配置 是否区分作用域
- 旧事实过期：是否停止使用
- 多条重复表达：是否合并
- 没有相关记忆：是否避免强行引用
- 提示词注入：是否阻止记忆污染

## 可观测性

一次完整请求统一 trace_id 串联

候选记忆如何产生 ->为什么写入或者被拒绝  -> 召回哪些候选  ->那些被过滤和原因 ->重排分数 ->最终注入 ->模型是否正确使用
