
单次 LLM 调用本身不会自动拥有之前的对话和业务状态；记忆由 Agent 应用负责保存、选择并重新提供给模型。

## 四类信息

模型上下文context ：
- 本质：本次llm可见的prompt 
- 生命周期：单次调用。
对话历史History 
- 本质：历史的消息记录 
- 生命周期：可以保存 但不一定要全量给模型 
任务状态state：
- 本质：是当前任务执行的进度
- 生命周期：通常任务结束就失效了
长期记忆Memory
- 本质：跨会话服用的用户事实 偏好 经验
- 生命周期：可本地持久化 可以检索

## 记忆分类

简单分就是短期和长期 长期包括实体。


- 感知记忆：当前输入的原始内容。
- 短期记忆：当前 Context Window 中的对话和任务信息。
- 长期记忆：持久化到外部系统、可以跨会话检索的信息。
- 实体记忆：从对话中提取的结构化事实、偏好、配置或状态。


记忆让 Agent 从单次问答工具变成可以保持连续性的助手，但“持久化了数据”不等于“模型已经记住”，只有相关信息被重新放入当前上下文时，模型才能使用。

## 记忆生命周期

```text
信息产生
→ 候选记忆提取
→ 价值与安全判断
→ 写入和索引
→ 检索与过滤
→ 注入当前上下文
→ 模型使用
→ 更新、整合、遗忘或删除
```


作用域越大，写入越谨慎；权限校验必须先于检索和注入。

## 最小记忆单元

记忆并不只是一个文本 最小记忆单元应该包含
**内容+来源+时间+置信度+作用域/权限**

如果 一个信息 
- 稳定
- 可复用
- 对任务有价值
- 用户允许保存
就可以进入长期记忆 一点不满足 就不会进入
