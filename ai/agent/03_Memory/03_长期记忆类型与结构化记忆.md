


长期记忆让 Agent 在跨 Session 或进程重启后仍可获取历史信息。关键不是保存全部聊天记录，而是保存未来任务可能复用的高价值内容。

适合保存：

- 用户明确且相对稳定的偏好；
- 任务中形成的重要决策和结论；
- 可复用的历史案例和经验；
- 项目配置、实体关系和关键事实。

## 三种长期记忆

#### 语义记忆

保存“是什么”的事实和一般知识，例如：

```text
用户主要使用 Python。
项目数据库使用 PostgreSQL。
```

适合保存：

- 用户偏好；
- 用户或项目属性；
- 实体事实与关系；
- 已确认的业务知识。

#### 情景记忆

保存“发生过什么”的具体经历，例如：

```text
上次排查 SQL Agent 时，问题来自错误的表名映射。
```

一个合格的情景记忆至少包括 时间+场景+行动+结果


#### 程序性记忆

保存“如何做”的可复用方法或操作经验、策略，例如：

```text
分析慢 SQL 时先检查执行计划，再检查索引和过滤条件。
```

程序性记忆适合保存尚在演化的个人经验。  
如果流程已经稳定、通用且必须严格执行，应固化到：

- 代码：要求确定性执行；
- Prompt：要求模型始终遵守；
- Skill：形成完整、可复用的工作流程。

结论：**动态记忆负责积累经验，代码、Prompt、Skill 负责固化稳定能力。**
## 结构化记忆

区分 语义、情景、程序化 回答的是记忆表达什么
结构化 非结构化回答的是 记忆如何组织。

因此语义、情景、程序化记忆 都可以结构化保存。

结构化一般是json格式 一条可靠记忆的最小结构为

{
  "content": "用户偏好中文回答",  #  记忆内容
  "type": "preference",  # 记忆类型
  "source": "用户明确表达", # 记忆来源
  "created_at": "2026-07-28", # 时间
  "confidence": 1.0, # 置信度
  "scope": "user" # 属于哪个用户 项目 或者组织
}


## 聊天记录

聊天记录持久化不等于长期记忆

聊天记录只是原始数据，通常包含：

- 重复表达；
- 临时要求；
- 错误尝试；
- 已失效信息；
- 与未来任务无关的内容。

高质量长期记忆是从历史中提炼出的：

> **少量、明确、可复用、可追溯的信息。**
