Memory 是跨任务复用的Agent经验和个体信息。 安全的核心是读写权限 保存时间 

所以需要保护两个入口
- 读： 防止不该访问的记忆被检索和注入
- 写：防止错误、恶意、越权的写入记忆
## 相关概念和memory的边界

- Conversation History 
	- 作用：保留原始交互记录
	- User Assistant、Tool  Message
- Working Memory 
	- 作用：支持当前llm推理
	- 当前目标、约束、必要上下文
- Runtime State
	- 程序确定性控制任务
	- 当前步骤 订单号 执行状态
- Long-term Memory 
	- 跨会话复用个体经验
	- 用户偏好 历史案例
- Cache
	- 提升性能
	- 重复请求结果 Embedding
- Rag
	- 提供外部知识
	- 产品文档 公司制度

## 安全边界

身份需要先于检索。

每条记忆归属于
- tenant_id 租户
- user_id 用户
- project_id 项目
- scope 领域

所以做法应该是 确认上述信息后 再允许返回的范围内检索 而不是先检索出来 再过滤。

## 提示词注入和记忆污染

风险来源：
- 外部网页
- 文件
- 邮件
- Tool Result
里可能包含提示词注入 不能写入长期记忆。

所以需要防污染做法：
1. 外部内容进来
2. 标记来源
3. 区分 数据 与指令
4. 提取候选事实
5. 校验权限 和 风险

原则：
- 外部内容默认不可信
- Tool Result 不能成为高可信记忆
- 模型推测不可升级为事实
- 可疑内容 先进入隔离区
- 关键事实由 用户 和系统确认

文本清洗无法做到彻底解决提示词注入 真正有效的是 权限隔离、来源标记、指令层级控制。

## 两个重点

删除数据要做到删除所有副本 覆盖全链路。

检索出来的数据只能作为数据 背景、不能作为指令
