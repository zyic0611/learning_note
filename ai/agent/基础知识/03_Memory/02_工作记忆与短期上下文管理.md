
短期记忆主要是当前模型调用可以看到的 Context Window，例如：

- 用户消息；
- Assistant 历史输出；
- Tool Call 和 Tool Result；
- 当前任务目标和中间结论；
- 必要的用户或运行时背景。

目标不是保留最多的历史 而是有限token预算内 保留完成当前任务所必须的信息。

## 三个概念

- 工作记忆
	- 是prompt中正在被模型使用信息 
	- 比如当前目标 最近对话 工具结果
- 会话历史
	- 系统保存的聊天记录 
	- 比如最近100轮消息
- 任务状态
	- 程序维护的确定性执行状态
	- 比如step、订单id

架构关系：

```
会话历史 / 任务状态
      ↓ 经过上下文策略选择
工作记忆（当前 Prompt）
      ↓
模型推理与行动
```

## context budget

上下文是预算 并非仓库

prompt的token空间要给不同内容分配位置

系统指令
+ 当前用户目标
+ 未完成计划 / 关键约束
+ 必要任务状态
+ 最近高相关对话
+ 完整工具调用链
+ 预留给模型输出的空间
优先级： 指令 目标 状态 工具链 历史只保留近端

裁剪的时候 优先删除 重复 闲聊 已完成 不复用的过程
不能删除
- system/developer instruction
- 当前目标与验收标准
- 未完成事项 限制条件 关键决策
- 精确id 文件名 参数等事实

### 三种上下文管理手段

### 滑动窗口与 Token 截断

适合多轮对话 短任务

原则：

- 窗口应该按 Token 预算管理，不能简单按对话轮数。
- System、Developer 等高优先级指令不能被普通历史截断策略误删。
- User/Assistant 交互以及 Tool Call/Tool Result 等协议消息应保持完整关系。
- 长上下文可能出现 Lost in the Middle，关键信息不应长期埋在中间位置。
- 越近的消息越重要 关键约束不能因为时间早而丢失

### 动态摘要

任务持续比较久 早期讨论仍有价值 但是原文太长。

当历史接近窗口上限时，可以把较早内容压缩为摘要：

```text
早期原始历史
→ 阶段摘要
→ 当前最近消息
```

好的摘要需要保留
```
目标 + 已确认约束 + 关键决策及原因
+ 当前进度 + 未完成事项 + 精确引用信息
```

摘要属于有损压缩，可能丢失：

- 精确代码和参数；
- 订单号、文件名等细节；
- 未完成约束；
- 细微语义变化。

因此 摘要负责帮助模型继续做事；  
**不能充当订单、支付、进度等权威事实来源。**


### 结构化状态外置

把确定事实交给程序。

适合：ID、金额、步骤、开关、参数、执行结果等不能出错的信息。

模型需要的时候 去读取状态。 不能让llm从长对话或者摘要中猜任务



### 常用裁剪策略

每次调用裁剪前：
1. 固定保留 ：指令、约束、当前目标、任务状态
2. 保留：最近若干轮高相关对话和完整工具链
3. 压缩：较早但是仍然有用的讨论为阶段摘要
4. 删除：重复内容 闲聊 已完成且无后续价值的对话
5. 留出输出token 避免模型回答被阶段。


**工作记忆的本质是：**
上下文编排 让llm每次调用中看到正确 足够 可信 有优先级的信息

**什么该留在 Context，什么该外置**
- 需要模型立即推理的内容：留在 Context。
- 必须精确、可校验、可恢复的执行事实：外置为 Runtime State。
- 早期过程但仍需延续：压缩为摘要。
