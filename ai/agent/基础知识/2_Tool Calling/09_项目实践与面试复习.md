# 项目实践与面试复习

## 需要学习什么

### 1. 完成一个完整项目

优先结合实际项目实现一个 Tool Calling Agent，不需要同时做多个浅层 Demo。

项目至少包含：

- 2～4 个职责清晰的工具。
- Tool Schema 和结构化参数。
- Tool Registry 和 Dispatcher。
- 完整 Agent Loop。
- 参数校验和缺参澄清。
- Tool Result 与 Grounding。
- 串行或并行工具调用。
- 一个需要权限或确认的写操作。
- 基础超时、错误和幂等处理。
- 调用日志和简单评测集。

### 2. 能画出系统架构

```text
User
→ Agent Runtime
→ Model
→ Tool Call
→ Registry / Dispatcher
→ Tool
→ Tool Result
→ Model
→ Final Answer
```

### 3. 能解释关键设计

- 为什么模型不直接执行工具。
- Tool Call 和 Tool Result 如何关联。
- Input Schema 和 Output Schema 分别约束什么。
- 模型参数和 Runtime 可信参数如何分离。
- Registry、Dispatcher 和 Agent Loop 如何协作。
- 如何处理缺参、工具失败和高风险写操作。
- 如何评测工具选择和任务完成质量。

### 4. 面试准备

- 准备一个完整项目介绍。
- 准备一次真实错误定位案例。
- 准备一个安全或权限设计案例。
- 能说明当前实现的限制和下一步优化方向。
- 能从用户请求开始，完整讲解一次工具调用链。

## 项目验收标准

- 可以运行，不只是伪代码。
- 工具调用链可查看和定位。
- 不会直接信任模型参数。
- 不会在工具失败时伪造成功。
- 写操作具备基本权限和确认机制。
- 至少有一组可重复运行的测试样本。

## 暂不要求

- 多 Agent 平台。
- 分布式 Tool Runtime。
- 通用 Workflow 或 DAG 引擎。
- 企业级监控和安全平台。
- 同时完成多个无关联 Demo。
