Goal 可以类比为推理时的优化方向，但它不是训练意义上的奖励函数。生产系统还需要把 Goal 转换成 **可验证的成功标准。**

是自然语言任务目标 描述偏好什么结果

由5部分构成
- Objective 想实现什么目标
- Acceptance Criteria 接受标准 什么结果算完成了
- Priority 多个目标冲突的时候 如何取舍
- Non-goals 明确不需要完成的目标 （比较少用 因为除了明确需要完成的 都不需要）
- Stop Condition 什么时候应该停止
```
目标：
根据用户问题生成可执行的只读 SQL。

验收标准：
- SQL 符合 MySQL 8.0 语法。
- 只能引用 Schema 中存在的表和字段。
- 不产生写操作。
- 能正确回答测试集中的业务问题。

优先级：
安全性 > 正确性 > 完整性 > 简洁性。（不一定 取决于什么业务场景）

停止条件：
SQL 已通过语法检查和只读检查；如果业务定义不足，则返回缺失信息而不是继续猜测。

```

## 验收标准

验收标准仍然可能不够测量 一般认为的是只要能正确回答测试集中的业务问题就行。 但是仍然不是具体的验收标准。

一般重点 **Goal必须能转化为Eval标准 而不是停留在形容词** 

so

```
- SQL 语法通过率 ≥ 99%
- 不存在字段引用率 = 0
- 写操作误生成率 = 0
- 测试集业务意图匹配率 ≥ 95%
- 需要澄清的问题，澄清准确率 ≥ 90%
```


## 停止条件

一般情况下只描述 成功的停止条件。

实际开发 需要描述

- 成功停止： 满足验收标准
- 澄清停止：缺少信息
- 失败停止：连续失败 权限不足 
- 升级停止：需要人工审批
