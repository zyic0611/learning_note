回答必须基于什么 系统提示词应该规定答案的依据。

```
优先使用提供的知识库和工具结果。
如果资料中没有答案，不要补充未经验证的事实。

回答时区分：
- 来源明确支持的事实
- 根据资料做出的推断
- 当前无法确认的内容

```

要区分 Grounding RAG Citation

**Grounding的作用是 引导模型 让模型的回答要基于指定上下文 、工具结果或者可信来源，**

RAG：只是一种获取上下文的技术

Citation：把回答中的内容 映射回具体来源 用于展示和审计。

## 严谨

并且 工具结果 不一定可信  知识库内容也可能过期 内容冲突 权限不匹配 被提示词防御污染 与用户当前状态不一致。

所以最好把  优先使用知识库和工具结果  修改为

```
根据不同信息类型定义可信来源优先级。

对于实时订单状态，以订单系统工具结果为准。
对于公司政策，以当前版本的官方文档为准。
对于用户权限，以权限服务返回结果为准。
如果来源冲突，不能自行选择并伪装成确定事实。
```

来源冲突 所以就要补充定义来源优先级

## 来源优先级

比如 需要 实时系统状态的时候

优先级 ：

当前权威业务数据库 > 当前版本官方文档 > 历史缓存 > 模型参数中的一般知识。

## 事实 推断 建议 的区分

一个llm完整的回答可以分为：

事实： 文档明确写出的内容

推断： 根据多个事实推测出的结果

建议： 基于事实和用户提出的行动 进行建议

未知：当前资料无法确认的事实

## 真正的grounding

不能只依赖 system prompt 

还要依赖

- 检索质量
- 文档切分
- 排序
- 来源权限
- 新鲜度
- 引用校验
- 答案事实检查

grounding 是系统能力 不只是提示词规则 prompt规定模型如何使用来源、检索与验证系统决定模型是否拿到了正确来源
