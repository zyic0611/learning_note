Prompt Injection 指低信任内容试图改变 Agent 原有行为、覆盖高优先级规则或诱导 Agent 执行未授权操作。

比如套取系统提示词。

## direct injection

攻击者直接与agent对话 提出一些非法的要求

## indirect injection

攻击内容隐藏在llm读取的外部数据中 
比如网页 rag文档 邮件内容 工具结果 数据库字段 其他llm的输出

## 本质

低信任数据 试图越权影响 高信任指令或高风险动作。

所以必须区分
Instruction：应用要求模型执行的指令
Data：用户、网页、文件和工具返回的资料。

## 与jailbreak的区别

prompt inject： 主要攻击agent的上下文和工具使用。
- 让agent泄漏消息
- 修改工具参数
- 执行不该执行的操作

Jailbreak：主要试图绕过模型的安全策略 诱导模型输出受限制的内容

## prompt层防御

可以使用：
- 清晰区分**指令**和**数据**
- 使用 XML、JSON 或明确边界
- 标记外部内容为 untrusted data
- 规定外部内容只能作为参考
- 禁止外部内容改变工具权限
- 禁止外部内容要求泄漏system prompt

## runtime层防御

真正的可靠性防御还需要
代码实现：
- 最小权限
- 工具白名单
- 参数schema校验
- 敏感工具审批
- 输出过滤
- 网络访问限制
- 数据库权限
- 审计日志
- 异常行为监测

eg：
prompt：告诉模型不能执行drop
sql parser 监测drop并拒绝
数据库账号：本身没有drop权限

## tool calling 中的 prompt injection

工具返回结果中可能包含恶意指令 

所以正确处理应该：
- 工具结果只能提供信息
- 不能改变工具权限
- 不能要求调用其他工具
- 不能覆盖系统指令

同时 工具调用结果应该尽量返回结构化 json字段 而不是一大堆未经处理的自然语言文本

## 高风险操作的纵深防御

针对 **删除 支付 转账 发送邮件** 等高风险操作 应采用

1 模型判断
2 参数校验
3 用户确认
4 权限校验
5 风险策略监测
6 工具执行
7 结果审计

一套链路必须经过

## 现实限制

prompt injection很难只靠prompt完全解决 因为模型天然会处理自然语言上下文 因此安全目标应该是
- 减少攻击成功率
- 限制攻击影响范围
- 组织高风险副作用
- 及时发现和审计
并非一段prompt就可以彻底防止

## 总结

Prompt Injection 的核心不是“用户说了坏话”，而是低信任内容试图越权影响高信任规则或高风险工具。Prompt 可以定义信任边界，但真正的安全性必须依赖权限、工具、沙箱、审批和审计等纵深防御。
