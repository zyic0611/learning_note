
## System Prompt 是什么

System Prompt 是由应用或平台预先提供的稳定指令，用来定义模型在整个任务中的：

- 身份
- 责任
- 目标
- 边界
- 行为规则
- 工具使用规则
- 输出契约
- 安全策略

## System Prompt 不负责什么

System Prompt 不能真正赋予模型：

- 新知识
- 新权限
- 新工具
- 数据库访问能力
- 业务系统操作权限

**它只能影响模型如何使用已经提供给它的能力。**

## 原则

system prompt **负责引导行为** 
代码、工具和权限系统负责强制执行。

## 静态和动态部分

system prompt 不一定是一整段固定文本

静态指令： static instructions
- 角色
- 目标
- 业务规则
- 安全规则
- 输出契约
静态属于系统提示词，通常承载稳定、长期、由应用控制的指令。

动态文本：
- 当前用户身份
- 当前时间
- 当前租户
- 当前任务状态
- 检索结果
- 用户偏好
- 工具状态
动态文本一般称为 Runtime context 运行时上下文
承载每次动态变化的身份 状态 检索结果 和工具结果。
动态内容有时可以被模版注入 system prompt 概念上仍然更接近 runtime context 


需要注意：

- 稳定规则适合放在 System/Developer Prompt。
- 当前任务和用户输入适合放在 User Prompt。
- 检索结果、网页内容和工具结果应明确标记为外部数据。
- 动态内容不能覆盖高优先级业务规则。

## 不是模型的 内核规则

 system prompt并非 绝对不可违背的模型底层规则 而是传递给模型的 高优先级消息。

仍然可能受到以下因素影响

- 模型能力
- 指令冲突
- 上下文过长
- 动态内容的 注入
- prompt injection
- 模型版本变化
- 工具返回错误
- 应用层 拼接方式

所以system prompt定义了什么 模型不一定会做。
只是提高遵循某种行为的概率 但不能单独保证行为一定发生。

## 模型行为

模型能力+指令+上下文+工具+运行时控制+配置 = 模型能力
