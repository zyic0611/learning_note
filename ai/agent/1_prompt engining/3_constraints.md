## 分类

内容约束：
- 不能编造事实
- 不能泄漏隐私
- 不能回答超出知识范围的问题

行为约束：
- 执行写操作前 必须获取确认
- 调用工具前 必须检查参数
- 信息不足时 必须先澄清

输出约束：
- 只能输出json
- 不包含额外字段
- 不超过多少字

资源约束
- 最多调用x次工具
- 最多执行x次重试
- 不能访问指定目录之外的文件


## 约束的强制等级

### 软约束：

依赖模型提示词：
- 使用简洁语言
- 按照某种制定顺序
- 输出某种风格

### 半硬约束

模型遵循提示词+ 应用层校验

- JSON Schema
- SQL语法
- 字段枚举
- 参数类型

### 硬约束

由代码 权限 沙箱 审批系统强制执行

- 数据库访问权限
- 文件访问范围
- 金额上限
- 是否允许删除

## 约束冲突

当约束冲突 也就是可能满足这个约束 就不满足那个约束了 互斥。 就必须定义约束优先级

比如定义 安全性>权限边界>正确性>完整性>简介性

如果无法同时满足所有约束：
- 优先满足高优先级约束
- 明确说明被牺牲的低优先级要求
- 必要时向用户确认

## 幂等性

对于有副作用的agent 要考虑幂等性 也就是操作的重复。

所以要告诉模型 事务边界
```
工具调用失败时，不要假设操作没有发生。
对于可能已经执行成功的操作，先查询状态，再决定是否重试。
```
