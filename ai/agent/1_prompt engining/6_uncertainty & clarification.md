不确定性处理 和 澄清问题

## 结果状态分析

主要是模型需要知道 

- 什么时候可以直接回答 
- 什么时候时候必须询问
- 什么时候可以做合理假设 
- 什么时候必须拒绝猜测假设。

这些是 生产 agent可靠性的基础。

提示词类似：

```
如果缺少信息，但可以通过低风险工具获取：
    先调用工具。
如果缺少信息，且不影响结果：
    明确列出假设后继续。
如果缺少信息，且会影响结果或产生风险：
    先澄清。
```

注意信息不足不一定要澄清 要区分：
- 是否真的影响任务
- 能否通过工具或检索自动补全
- 做这个假设的风险有多大 

## 原因角度分析

- 语义不确定 ： 用户提问的问题不清楚
- 事实不确定： 知识库没有讲起你感触 llm没有可靠依据
- 状态不确定： 工具返回的请求超时 不一定失败 可能是成功了 没有返回结果
- 权限不确定：模型不知道用户是否有权限。

这四种不确定性的处理方式不同 不能全部返回 信息不足 不知道。

## 澄清问题的 三个原则

最小化： 一次只问完成任务所必需的问题

可回答： 不要问用户无法理解的内部字段 要更自然语言化

有优先级： 如果缺少五个字段 不要一次问五个问题 优先问最能缩小决策空间的问题。
```
一次最多提出 3 个问题不是固定定律，
应根据任务复杂度和用户体验通过评测确定。
```

## 合理假设需要有边界

并且要说明 假设 允许什么 禁止什么

## 澄清后的状态保持

这个涉及到 节点状态或者上下文状态了。 澄清后要获取上文状态。
