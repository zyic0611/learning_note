## 作用
是在提示词中提供若干 输入-输出示例 让模型从示例中学习：
- 格式
- 输入与输出之间的映射
- 任务边界
- 业务口径
- 工具选择方式
- 澄清方式
- 异常处理方式
- 拒绝回答条件
- 风格与粒度
- 边界案例
## 好的示例标准

- 与真实任务高度相关
- 具有代表性：典型场景
- 多样性：覆盖边界和异常情况
- 正确性：输出经过验证
- 简洁性：不包含无关信息
- 安全：bu ba不包含真实密钥、隐私或危险操作
## 静态few-shot

固定放入 System/Developer Prompt。
适合任务稳定、示例数量较少的场景。

## 动态few-shot

运行时从示例库中检索相关案例。
本质上属于 Example Retrieval +Context Engineering。

动态检索不能只看向量相似度
还需要考虑：

- 领域和 Schema 是否一致
- 业务版本是否一致
- 权限范围是否一致
- 是否没有过期
- 是否经过验证
- 是否覆盖当前边界

## 示例选择

不应该只选取最相似的五个示例 因为他们可能高度重复。

更好的策略：
1. 先召回相似候选
2. 过滤错误 过期 权限不匹配的案例
3. 选择能够覆盖 不同模式 的示例
4. 加入少量边界案例和反例
5. 控制token数量

## 分类

zero-shot： 没有示例 只给任务说明

one-shot：只提供一个示例

few-shot： 提供少量示例

multishot：提供多个示例 强调用多个案例覆盖任务模式

## 结论：
Few-shot 不只是教格式，还可以教任务边界、决策模式和异常处理。静态 Few-shot 属于 Prompt 设计，动态 Few-shot 属于 Example Retrieval 和 Context Engineering。示例的质量、覆盖度和适用性比数量更重要。
