YAML配置文件 实现企业别名的映射

## 静态映射：YAML 配置文件的维护

系统不会将别名逻辑写死在 Java 或 Python 代码的 `if-else` 中，而是抽象到了外部的YAML 配置文件。这种设计实现了代码与业务规则的解耦，方便实施人员随时热更新。

YAML 文件中维护的是一张高频别名的二维映射表，结构类似如下：

```yaml
enterprise_aliases:
  - keywords: ["玉禾田", "玉禾田环境"]
    sql_condition: "LIKE '%玉禾田%'"
  - keywords: ["盈峰", "盈峰环境", "中联重科环境"] # 中联重科环境被盈峰收购，业务上常混用
    sql_condition: "LIKE '%盈峰%' OR LIKE '%中联重科环境%'"
  - keywords: ["侨银", "侨银环保"]
    sql_condition: "LIKE '%侨银%'"
```

## 运行时动态侦测与片段组装

当用户的 query（例如：“查询一下盈峰环境和玉禾田今年在华东区的清扫项目”）进入系统后，引擎会执行以下流水线操作：

- **文本探针扫描**：系统在**运行时**，利用 Aho-Corasick 自动机或简单的正则遍历，将用户的 query 与 YAML 文件中的 `keywords` 列表进行快速交叉比对。
- **按需动态拼接**：系统发现 query 命中了“盈峰环境”和“玉禾田”。此时，代码会**仅提取**这两家企业对应的 `sql_condition`，并在内存中组装成一小段文本（即所谓的“片段”）。
- **Prompt 局部注入**：系统将组装好的片段插入到发给大模型的系统提示词的特定占位符中。

最终大模型看到的 Prompt 会多出这样一段极为明确的指令：

> **【企业检索词映射规则】** 当你需要过滤以下企业时，严禁使用等于号（=），必须严格使用以下 SQL 片段：
>
> - 玉禾田 → LIKE '%玉禾田%'
> - 盈峰环境 → LIKE '%盈峰%' OR LIKE '%中联重科环境%'

## 底层逻辑

大模型在生成 SQL 时，最大的弱点是“不知道数据库里真实的数据长什么样”。它只能凭借预训练的常识进行推理。

“企业别名片段”的本质，就是一种**Just-In-Time（即时）的知识外挂**。它相当于在模型提笔写 SQL 的前一秒，给它递了一张小纸条：“别猜了，业务库里的规则我都给你查好了，直接照抄这几句 LIKE 条件即可。” 这种确定性的规则约束，极大地压制了模型在模糊查询（Fuzzy Match）场景下的幻觉，保证了数据看板和统计报表的口径绝对准确。
