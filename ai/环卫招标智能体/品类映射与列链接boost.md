理解品类映射是如何命中的，核心在于看透系统在用户自然语言和物理数据库列名之间，构建了一个中间语义层或元数据知识库。

## 静态字典和同义树

这是最基础、最精准，也是企业应用中最依赖的命中方式。系统会在底层维护一个**业务领域字典**

**运行机制**：数据产品经理或开发人员会预先录入业务中的黑话、简称、口语化表达（如“板块”、“大类”、“业务线”），将其作为同义词统一挂载到标准概念（如“项目大类”）下，并与物理列名 `SanitationProjectBigType` 进行强绑定。

**命中过程**：用户的 query 输入系统后，首先进行**分词（Tokenization）**，随后通过**Aho-Corasick 自动机**等多模式匹配算法在字典中进行极速扫描。一旦扫到“板块”这个词组，系统即刻触发“项目大类”的映射规则。



## 枚举值与业务注释的向量化检索

此方法用于兜底字典无法覆盖的新词或模糊表达，实现语义层面的泛化命中。

**运行机制**：系统初始化时，不仅对列名进行**Embedding**，还会将该列中的**高频枚举值**（例如 `SanitationProjectBigType` 列里的具体数据：环卫、绿化、水务）以及**列的业务描述**拼接后存入向量数据库

**命中过程**：当用户问“环卫和水务的毛利对比”时，尽管完全没提“板块”或“大类”，但 query 与 `SanitationProjectBigType` 列内的枚举值向量在多维空间中距离极近（Cosine Similarity 高）。系统据此判定用户隐式指向了该列，从而命中映射。



## LLM 预处理与意图槽位提取

针对极其复杂的长句或隐含意图，系统会引入一次轻量级的大模型调用来进行前置分析。

**运行机制**：在进入核心的列链接逻辑前，系统先通过一个专用的 Prompt 让模型做命名实体识别（NER）或意图分类。例如设定提示词：“请提取用户问题中的分析维度，可选范围：[时间、地理位置、业务板块...]”。

**命中过程**：模型解析“各板块占比”后，输出结构化的 JSON 结果：`{"Dimension": "业务板块"}`。后端代码接收到该信号后，比对硬编码配置，直接激活对应的规则 ID。

## 命中后的 Boost提权 执行流

一旦上述任意一种机制成功“命中”了业务映射，系统会将这种认知转化为对 Schema 检索的干预：

1. **规则激活**：系统记录当前 query 命中了特定的业务规则（例如 `Rule_ID_Category`）。
2. **生成白名单**：系统读取该规则的配置，配置声明了完成此类分析**必须包含**的物理列集合（如 `SanitationProjectBigType`）。
3. **强制绕过截断（Bypass Top-K）**：在随后的常规打分环节，即便 `SanitationProjectBigType` 这列在 BM25 或基础向量检索中的得分极低、跌出了 Top 32，系统也会利用白名单特权，强制将其“塞入”最终发给大模型的 Prompt 表结构中，彻底消灭因截断导致模型无法生成正确 SQL 过滤条件的问题。
