# Agent 开发中 LLM 如何选型（面试复习版）

> 面试题：平时开发 agent 时，LLM 如何选型？不同环节用什么 LLM？每种 LLM 有什么特点？

---

## 0. 一句话开场（先把方法论抛出去）

> 我选型 LLM 的核心原则是 **"分层路由 + 按环节匹配能力"**，而不是用一个模型打天下。先看任务处在 agent 的哪个环节、需要什么能力（推理 / 工具调用 / 抽取 / 长上下文），再看成本和延迟约束，最后才落到具体模型上。同时我会做**模型抽象层**，保证可替换、可降级。

这句话说出来，面试官就知道你不是只会背模型名，而是有工程思维。

---

## 1. 选型的 5 个维度（先讲框架）

| 维度 | 问的问题 |
|---|---|
| **任务复杂度** | 需要多步推理/规划，还是简单的抽取分类？ |
| **能力类型** | 推理？工具调用？长上下文？多模态？代码？ |
| **成本 & 延迟** | 这个环节是高频调用还是低频关键路径？能接受多慢/多贵？ |
| **上下文窗口** | 要喂多少背景（整个代码库？长文档？） |
| **合规/数据** | 数据能不能出内网？要不要私有化部署？ |

**金句**：`模型能力、成本、延迟是个不可能三角，选型就是在三角里找每个环节的甜点区。`

---

## 2. 核心思想：分层路由（Tiered Routing）

这是 agent 工程里最关键、最能体现水平的一点：

- **大模型做"脑"**：规划、推理、复杂决策、多步编排 —— 用最强的。
- **小模型做"手"**：抽取、分类、结构化、格式化、摘要、简单改写 —— 用最快最便宜的。
- **中间加 Router / 级联（cascade）**：先让便宜模型试，置信度不够再升级到大模型；或用分类器路由。

> 实测一个 agent 里 **80%+ 的调用其实都是"手"类任务**（JSON 抽取、字段判断、格式对齐），如果全用旗舰模型，成本会爆炸、延迟也高。分层之后能降 10 倍以上成本。

---

## 3. 按环节映射模型（重点，直接背）

| Agent 环节 | 需求 | 推荐模型层级 | 原因 |
|---|---|---|---|
| **规划 / 编排（Planner / Orchestrator）** | 多步推理、任务分解 | 旗舰推理模型：Claude Opus 5 / GPT-5 / Gemini 2.5 Pro / DeepSeek R1 | 这是"脑"，错误会级联放大，必须最强 |
| **编码 / 复杂 agentic 任务** | 工具调用 + 代码生成 + 长上下文 | Claude Sonnet 5（默认首选）/ GPT-5 / Gemini 2.5 Pro | Sonnet 在 agentic coding 上是公认的甜点 |
| **工具调用 / Function Calling** | 稳定、准确地调用工具、传参 | Claude Sonnet 5 / GPT-5 / Gemini Flash | 要"听话"、格式稳定，不是越强越好 |
| **抽取 / 分类 / NER / 摘要** | 结构化输出、量大、高频 | 小模型：Claude Haiku 4.5 / Gemini 2.5 Flash / GPT-4o-mini / DeepSeek V3 | 便宜快，能力完全够 |
| **结构化输出（JSON Schema）** | 严格 schema 对齐 | 小模型 + constrained decoding | 用结构化输出能力，而不是"劝"模型输出 JSON |
| **RAG 检索** | 语义相似度 | 专用 embedding 模型（**不是 LLM**） | embedding ≠ 生成模型，别混用 |
| **LLM-as-Judge / 评测** | 客观评分、对错判断 | 强模型（Opus 5 / GPT-5），甚至双模型交叉 | 评判者要够强，否则评测失真 |
| **兜底 / 改写 / 打招呼** | 低价值但高频 | 最便宜模型或本地小模型 | 杀鸡不用牛刀 |
| **敏感数据 / 私有化** | 数据不出内网 | 开源本地：Qwen / Llama / Mistral / GLM | 合规优先于能力 |

## 4. 各模型家族特点（背这一块）

### Anthropic Claude
- **强项**：agentic coding 和工具调用是当前公认最强梯队；长上下文（200K+）；prompt caching 做得好；安全对齐好；风格自然不啰嗦。
- **家族分层**：Opus（旗舰，最强推理）/ Sonnet（性价比之王，agent 默认款）/ Haiku（快 + 便宜，做抽取）。
- **相对弱**：贵、速率限制有时紧、多模态不如另外两家全面。

### OpenAI GPT
- **强项**：生态最全（function calling / structured outputs / vision / audio / reasoning 全家桶）；多模态强；o 系列推理模型数学代码强。
- **家族分层**：GPT-5（旗舰）/ GPT-5-mini 或 4o-mini（便宜款）/ o 系列（慢但深推理）。
- **相对弱**：上下文窗口比 Gemini/Claude 短；旗舰贵；有时话多、格式啰嗦。

### Google Gemini
- **强项**：**上下文窗口碾压级**（1M～2M tokens，能一次塞进整个代码库或超长文档）；原生多模态最强；性价比高（Flash 极便宜）；Google 生态。
- **家族分层**：2.5/3 Pro（旗舰推理 + 超长上下文）/ 2.5/3 Flash（又快又便宜，小任务神器）。
- **相对弱**：工具调用 / agentic 稳定性略逊于 Claude；偶发安全过滤过严或输出格式不稳。

### DeepSeek
- **强项**：**性价比之王**，API 价格极低；开源可自部署；中文强；R1 推理模型数学/代码强。
- **家族分层**：V3（通用，便宜好用）/ R1（推理，慢但强）。
- **相对弱**：生态和工具链没海外三家成熟；多模态弱；对海外业务有数据合规顾虑；稳定性波动。

### 开源本地（Qwen / Llama / Mistral / GLM）
- **用在哪**：数据不能出内网、要私有化、要做垂直领域微调的场景。
- **代价**：要自己部署运维（GPU 成本、量化、推理优化），能力天花板低于闭源旗舰。

## 5. 能加分的实战细节（Senior 感拉满）

1. **模型抽象层**：写一个 `LLMProvider` 接口统一封装，所有调用都走它，模型可热切换、可 A/B、可降级。面试官会问"模型挂了怎么办"——答案是有 fallback。
2. **Fallback / 降级链**：主模型超时/限流 → 自动切次选模型 → 再切便宜模型重试。关键路径绝不能单点依赖。
3. **结构化输出**：能用 `response_format=json_schema` / constrained decoding 就用，别靠 prompt 去"求"模型输出合法 JSON。
4. **Prompt Caching**：长 system prompt + 多轮工具调用场景，缓存能省 90% 成本和延迟，尤其 Claude/Gemini。
5. **温度控制**：推理类模型（o/R1 系列）temperature 要固定、别乱调；抽取分类类直接设 0。
6. **观测与成本监控**：每个环节打标（哪一步、哪个模型、多少 token、多少成本、延迟多少），用数据反推哪个环节可以降级到小模型——这是"用数据说话"的选型。
7. **版本 Pin**：模型号要锁定（用带日期/版本的 ID），别用会静默升级的别名，否则线上行为会漂移。
8. **Router 逻辑**：任务先过分类器判断复杂度，简单任务直接发小模型，复杂任务发旗舰——这就是"按需用强"。

## 6. 如果被追问"你怎么保证选型是对的"

标准答案：**用评测和灰度说话，不拍脑袋。**

- 建一个 **agent 环节评测集**（每个环节的典型任务 + 黄金答案），对不同模型跑分。
- 关注指标不只是"准确率"，还有 **成本 / 延迟 / 工具调用成功率** 的联合权衡。
- 线上做 **灰度 A/B**，用真实流量验证，再逐步切换。
- 结论往往是：**没有"最好"的模型，只有"某个环节最合适"的模型。**

---

## 7. 收尾补一句实话

模型版本迭代极快（2026 年已经到 Claude 5 家族、Gemini 3、GPT-5 这一代），具体型号每年都在变。面试官真正考的是你有没有 **"分层路由 + 按环节匹配 + 可替换降级"这套框架**，而不是你背没背下最新版本号。框架对了，型号更新只是换表而已。

## 附：速记卡（一分钟过一遍）

- **一句话**：分层路由 + 按环节匹配能力。
- **5 维度**：复杂度 / 能力 / 成本延迟 / 上下文 / 合规。
- **三角**：能力 × 成本 × 延迟，找甜点区。
- **脑 vs 手**：大模型做脑（规划推理），小模型做手（抽取分类），80% 是手类任务。
- **按环节**：规划→旗舰推理；编码/工具→Sonnet；抽取→Haiku/Flash/mini；RAG→embedding；评测→强模型；私有化→开源本地。
- **四家特点**：Claude 强在 agentic + 工具调用；GPT 生态最全 + 多模态；Gemini 上下文最长 + 便宜；DeepSeek 性价比 + 中文 + 开源。
- **工程加分**：抽象层 / fallback / 结构化输出 / prompt caching / 温度 / 监控 / 版本 pin / router。
- **怎么证明对**：评测集 + 成本延迟权衡 + 灰度 A/B。
