**`ChannelPipeline`**：每个 Channel 被创建时，都会自动创建一个属于它的 Pipeline。它就像是一条工厂流水线。

**`ChannelHandler`**：流水线上的工人。数据在 Pipeline 中流动，依次经过一个个 Handler 的处理。

- **`ChannelInboundHandler`（入站处理器）**：处理“进来”的数据。比如：`接收原始字节 -> 粘包拆包解码 -> 反序列化为 Java 对象 -> 执行业务逻辑`。它的执行顺序是**从前往后**（`Tail` 方向）。
- **`ChannelOutboundHandler`（出站处理器）**：处理“出去”的数据。比如：`业务层写出对象 -> 序列化为字节 -> 编码包装 -> 写入网络发走`。它的执行顺序是**从后往前**（`Head` 方向）。

## 设计原理

###  一个chanel绑定一个eventloop

为了**彻底避免线程切换和锁竞争**。Redis 之所以快，就是因为单线程省去了锁的开销。Netty 让一个连接的所有 IO 操作都由同一个线程执行，意味着你在写自定义 Handler 时，根本不需要担心线程安全问题，数据流在同一个线程里顺流而下，效率极高。
