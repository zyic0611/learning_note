是一种 设计 web api 的架构风格 本质上是一个api设计风格 并不是一个具体的协议

核心思想： 把**业务对象抽象成资源** 通过 http的 标准方法 对资源进行操作



这就是把用户这个对象 抽象成一个资源 对资源在操作
GET    /users/123      查询用户
POST   /users          创建用户
PUT    /users/123      修改用户
DELETE /users/123      删除用户

并且是**无状态**的  服务器不保存 客户端请求之间的会话状态  所以每次请求都应该包含这次请求所需要的全部信息 不能省略。

并且强调 **统一接口** 不同资源都使用一套HTTP操作方式 搭配 http的方法 来表示操作 get/post/put/delete 再配合统一的状态码、请求格式、相应格式

客户端不需要知道服务内部具体调用什么方法 只需要知道 http格式的操作资源



## 绑定数据格式

REST API 的 返回数据格式 可以是 json、也可以是xml 纯文本 html 没有强制绑定关系。 这些只是数据表示格式。  但是一般用json 比较简单 轻量 容易解析 适合前后端数据交互。
