核心一句话：

> **TCP 只负责把一串字节可靠地从 A 传到 B，它不知道这些字节代表几个请求、几个响应。**

例如客户端连续发送两个请求：

```
请求1：HELLO
请求2：WORLD
```

TCP 看到的只是：

```
HELLOWORLD
```

它可能分成：

```
HELLO
WORLD
```

也可能：

```
HEL
LOWOR
LD
```

甚至一次全部收到：

```
HELLOWORLD
```

TCP **不会告诉应用层：“这里是请求1结束了，那里是请求2开始了。”**

---

### 那请求/响应边界是谁负责？

**上层协议负责。**  所以HTTP是应用层协议 核心作用是定义数据的规则

例如 HTTP：

```
TCP
↓
HTTP
↓
通过 HTTP 协议规定的格式判断请求/响应边界
```

HTTP/1.1 可以通过 `Content-Length`、`Transfer-Encoding: chunked` 等方式确定消息边界。

RPC 协议也一样，需要自己定义：

```
[消息长度][消息类型][请求ID][数据]
```

接收方根据协议解析出完整消息。


所以会出现粘包的问题 拆包需要由应用层协议来处理
