## 1. 四个概念

### 推理：当前应该怎么判断

推理（Reasoning）是模型根据当前 Context 和 State 分析信息并形成判断的过程，例如：

```text

现有证据不足

→ 还需要查询服务日志

```


它可能产出直接答案、Tool Call、澄清问题或计划，不一定是一个独立的外显节点。 是模型的一个行为。
### 规划：为了目标需要经过哪些步骤

规划（Planning）是模型可以执行的一类推理任务。它把目标转成步骤、依赖和完成条件，并把结果作为候选计划输出。 它也是模型的一个行为。

规划关注的是全局路径。它不是完整思维链，而是 Runtime 可以解析和校验的外显任务结构。

### 执行：把当前行动真正做出来

执行（Execution）负责完成当前步骤，例如调用日志工具、查询数据库或生成文件。

模型可以提出候选行动，但真实工具仍由 Runtime 校验和调用。

### 编排：让整个流程可靠运行

编排（Orchestration）负责状态持久化、节点调度、并发、重试、恢复、审批等系统问题。

它不负责理解用户语义，而是保证决策和执行能够稳定推进。

编排主要是runtime控制的 确定性程序编排。


## 3. 一个例子
用户提出：

```text

支付接口延迟突然升高，帮我定位原因。

```
如果 Runtime 进入 Planner 节点，模型会在内部判断当前信息不足（这一步就是推理），并输出候选计划：

```text

确认异常时间范围

→ 定位延迟增加的节点

→ 查询相关日志和下游指标

→ 验证候选根因

→ 输出结论

```

执行层调用 Metrics、日志等工具。
编排层保存每一步状态，处理工具超时和任务恢复。

**这里不是必须先经过一个独立“推理节点”，再进入“规划节点”。模型在生成计划时，本身就在进行推理。**

  

## 4. 总结


**推理是模型内部分析信息并形成判断的过程；规划不是推理之后必然发生的第二阶段，而是一类以“生成候选执行计划”为目标的推理任务。Planner 输出计划，Runtime 负责解析、校验和执行。**
