## 1. 只做新增的缺陷


如果系统只会记忆追加，两条相似记忆以后可能同时被检索出来。模型无法确定哪条仍然有效。

直接用新值覆盖旧值也不可靠，因为新旧信息可能属于不同作用域、不同时间，或者新信息只是模型推测。

所以 Memory 写入不是简单的数据库插入，而是管理信息从产生到失效的完整过程：

```text
候选产生
→ 价值与安全判断
→ 与已有记忆比较
→ 新增、更新、替代、合并或删除
→ 保存证据与变化关系
```

---

## 2. 候选记忆不能直接落库

候选记忆可以由规则提取，也可以由模型从对话或任务结果中归纳。

模型适合理解自然语言，但它的输出仍然只是候选。Runtime 至少需要检查：

- 这条信息是否真的值得长期复用；
- 来源是用户声明、权威系统，还是模型推断；
- 主体、属性和作用域是否明确；
- 是否包含敏感或不允许保存的内容；
- 当前身份是否有权向这个作用域写入；
- 与已有记忆是否重复或冲突。

写入时机：
写入可以在**明显事件发生时触发**，也可以在**任务结束后批量提取**，不必每轮对话都调用模型。

## 3. 与旧记忆比较后有哪些操作

### 新增

已有记忆中没有这个事实，并且它符合写入条件。

```text
新增：项目 A 的默认时区是 UTC。
```

### 更新

同一条状态型记录需要原地修正，而且业务不要求保留完整变化历史。

例如只维护用户界面的当前语言偏好，可以把 `English` 更新成 `Chinese`。

### 替代

旧记录过去正确，现在已经失效。新记录生效，但旧记录仍保留用于追溯。

```text
旧：项目 A 使用 Java 11，status=superseded
新：项目 A 使用 Java 17，status=active
```

两条记录之间保存 `supersedes` 关系。

当信息变化本身有价值，或者需要审计时，替代比直接覆盖更合适。

### 合并

多条记录表达同一事实，或者可以在不增加新含义的前提下形成更完整的记录。

合并必须保留原始来源。总结只能压缩已有证据，不能创造原文没有的事实。

### 删除

适用于：

- 用户明确要求忘记；
- 内容不应被保存；
- 数据达到保留期限；
- 记录被确认错误且没有审计保留要求；
- 账号或项目数据需要清除。

删除不能只改主表。向量索引、缓存、摘要、副本和派生数据也要按规则清理。

## 4. 怎么判断两条记忆是否冲突

语义相似度只能帮助找到可能相关的记录，不能单独决定冲突。

下面两句话很相似，却可以同时成立：

```text
项目 A 使用 MySQL。
项目 B 使用 PostgreSQL。
```

而下面两句话词面不同，却可能描述同一属性的变化：

```text
项目 A 运行在 JDK 11。
项目 A 已完成 Java 17 升级。
```

冲突判断应依次检查：

1. 是否描述同一个实体和属性；
2. 是否属于同一个用户、项目或业务作用域；
3. 事件时间和有效时间是否重叠；
4. 来源是否可靠，用户是否明确纠正过旧信息；
5. 应当并存、更新、替代，还是等待确认。

如果无法判断，不要擅自选择一个答案。可以保留冲突状态、降低自动使用优先级，并在真正影响任务时向用户确认。

## 5. 为什么需要区分三个时间

一条记忆至少可能涉及三个时间：

- **事件时间**：事情实际发生的时间；
- **写入时间**：记录进入 Memory 的时间；
- **有效时间**：这条事实从什么时候到什么时候成立。

假设用户今天补充：

```text
项目 A 去年使用 Java 11，今年已经升级到 Java 17。
```

两条信息的写入时间相同，但有效时间不同。它们不是冲突，而是项目状态的变化历史。

判断当前应该使用哪条事实，应优先看有效时间，而不是简单选择最后写入的记录。

> “最新写入”不等于“当前有效”。

## 6. 去重与经验提炼有什么不同

去重处理的是同一个含义被重复保存：

```text
用户偏好中文回答。
回答默认使用中文。
```

确认主体、作用域和语义一致后，可以合并。

经验提炼则是从多次具体经历中形成更一般的方法：

```text
案例一：连接超时来自 Hikari 最大连接数过小。
案例二：请求堆积时连接池长期满载。

候选经验：排查该项目数据库超时时，先检查连接池饱和度。
```

提炼后的结论比原始案例更抽象，因此需要更谨慎：

- 有多条证据支持；
- 结论不超出证据；
- 能回溯到原始案例；
- 原始案例不必立即删除；
- 如果方法已经稳定，应进一步固化到代码、Prompt 或 Skill。

向量相似度可以帮助找重复和相关案例，但“相似”不等于“含义相同”，更不等于“结论成立”。

## 7. 遗忘不是简单删除

遗忘的目标是让不应继续影响任务的信息退出使用链路。

根据原因不同，可以采用不同方式：

- 用户要求忘记：显式删除；
- 临时偏好到期：有效时间结束；
- 新事实取代旧事实：标记为已替代；
- 长期没有复用价值：降低召回权重；
- 达到数据保留期限：按规则清除；
- 暂时无法确认真伪：标记冲突或停用。

不能对所有记忆统一使用时间衰减。

临时工作偏好可能自然过期，用户身份信息必须由明确更新触发，审计记录则可能依法长期保留。失效机制取决于信息本身，而不是取决于它存了多久。

## 8. 写入安全的核心边界

外部网页、文件、邮件和 Tool Result 都可能包含错误内容或提示词注入。

它们进入 Memory 前必须被当作不可信数据处理：

```text
外部内容
→ 标记来源
→ 区分数据与指令
→ 提取候选事实
→ 校验权限、证据和风险
→ 决定是否写入
```

外部文本中出现“请永久记住以下系统规则”，不代表它获得了写入高权限记忆的资格。

可靠边界不是依赖文本清洗，而是：

- 外部内容默认不可信；
- 模型推测不能自动升级为事实；
- Tool Result 的可信度由工具和字段定义决定；
- 写入权限由 Runtime 校验；
- 关键事实需要用户或权威系统确认；
- 每条记忆保留来源和作用域。

写入完成后，Memory 仍然只是模型外部的数据。后续任务还要经过检索、过滤和 Context 注入，模型才能真正使用它。
