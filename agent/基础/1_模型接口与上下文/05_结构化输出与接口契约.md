
## 1. 为什么自然语言输出会成为系统问题

如果模型只面向用户回答，自然语言通常已经足够。

但在 Agent 中，模型结果经常要交给 Runtime 或下一个节点：

```text
模型识别意图
→ Runtime 读取意图
→ 选择工作流分支
→ 调用对应工具
```

如果模型返回：

```text
用户看起来应该是想退款，不过也可能只是在咨询。
```

人可以理解，程序却难以稳定判断下一步。

因此，当输出需要被程序消费时，就需要接口契约：

> 输出契约定义模型必须返回什么结构，以及每个字段在业务上代表什么（定义schema）。

---

## 2. 输出层级

输出为**自然语言** 专门给人类阅读 此时不需要结构化

**prompt约束** 要求返回json 但是prompt约束 模型可能不遵循、并且漏掉字段、改变字段名等等

**json mode** 模型api有约束生成机制 可以保证输出的 复合json语法

**Structured Outputs**  是模型api的约束生成机制 可以保证 json+ schema

**应用层校验** 可以校验json、schema、业务规则、权限 最后决定是否放行

**tool call** 本质也是json+schema 语义上是给runtime提供一个行动建议 runtime还是需要校验工具 参数 权限 等等



---

## 3. 契约其他内容

接口契约只定义 JSON 形状还不够。

### 结果语义

契约需要规定：

- 有哪些结果状态； 最好是枚举值 下游好消费
- 每个状态需要哪些业务字段；
- 哪些字段必填；
- 状态和字段之间有什么约束。


### 依据与错误信息

需要规定：


- 结论依据来自哪个工具、文档或数据；
- 错误类型和错误码；
- 哪些信息可以暴露给用户；
- 哪些内部信息只能交给 Runtime；
- 模型认为是否值得重试。

但这里要明确：
 模型只能提供判断信息，真正是否重试、换模型、重新检索或路由到人工，由 Runtime 决定。
数据库超时、权限失败等系统错误也应该由 Runtime 或工具产生，不能让模型猜测。

### 特殊值语义
必须提前定义：
```
null      → 已知该字段目前没有值
[]        → 查询成功，但结果集合为空
字段缺失   → 当前状态下不适用，或协议允许省略
```

## 总结

结构化输出就是规定模型的输出 模型的输出不一定是自然语言。

结构化输出契约不仅规定 JSON 和 Schema，还要规定状态、状态对应的数据、判断依据、错误语义和特殊值语义。模型负责按照契约提供判断结果，Runtime 负责校验、重试、路由和执行。
