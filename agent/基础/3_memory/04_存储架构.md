```text
是否主要按用户、项目、实体和状态精确查询？
→ 是：先使用关系数据库

是否需要按自然语言含义检索大量非结构化记忆？
→ 是：在事实源之外增加向量索引

是否存在明确 Key 的高频、低延迟或临时数据？
→ 是：增加 KV 层

是否频繁查询复杂的多跳实体关系？
→ 是：再评估图数据库
```



## 常见混合架构

当需求确实同时包含精确管理、语义检索和高频读取时，可以形成：

```text
                 ┌→ 向量索引：召回相似内容
记忆写入 → 关系库
                 └→ KV：缓存热点数据和检索结果
```

多个存储同时存在会带来新的成本：

- 数据同步；
- 一致性；
- 删除传播；
- 索引重建；
- 故障恢复；
- 可观测性和运维。

只有单一存储无法以可接受的质量和成本支持查询时，才值得升级为混合架构。
