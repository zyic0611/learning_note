模型一次工作使用的是context，如果进行多轮对话，没办法把完整聊天记录都放入context。会导致
- token高
- 干扰判断
- 核心信息难以复用
所以runtime需要把未来可能还会用到的信息保存在llm外 也就是memory 并且后续任务按需取。

## 两阶段

- 写入：把需要的信息持久化
- 读取：从memory中读取需要的信息

这两部共同构成了memory 并非只是存在库里。

## 与其他的边界
history 可以全部持久化 作为全量保存 作为审计、回放、摘要、记忆提取的原始材料 

memory是从history里提取出来的 少量 长期有用信息 

context 是本轮对话给模型看的内容 一般只放最近几轮对话 摘要历史 任务状态 工具结果 检索出来有用的
context 就是本轮工作台 prompt是context里指导模型行为的部分

## 核心问题

memory让agent具有连续性 但是不能保证记忆正确 也不能代替权威业务数据。 
会带来问题 大量信息 什么值得写入。
