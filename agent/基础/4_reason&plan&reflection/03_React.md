因为很多任务没办法提前规划好 这种一般存在于局部。 因为整体目标一般清晰 但是局部一般需要边做边得出结论 也就是局部路径不确定。

这部分任务的下一步行为 就取决于刚获得外部结果（observation） 。

## 核心
所以react的核心就是一个决策循环 决策和观察交替进行。

读取目标和当前状态
→ 模型选择下一步行动
→ Runtime 校验并执行
→ 获得 Observation
→ 更新状态
→ 模型决策继续行动或结束

新的observation必须能改变后续判断 如果无论工具返回什么结果 都固定路由 此时就适合workflow。

## observation

模型每轮决策需要看到
- 当前目标
- 已确认事实
- 还需要做的任务
- 已完成的任务
- 剩余预算
- 等等
这样可以防止目标飘逸 重复查询 无限探索

## 无效循环

一次新行为应该起码带来一种进展
- 获取完成目标所需要的新事实
- 排除一个候选假设
- 缩小未解决的问题

## 结束情况
- 目标完成
- 信息不足 需要澄清
- 资源预算/权限不足
- 进入无效循环

## 场景
很适合路径依赖 **外部结果** 的探索、诊断、检索任务。
不适合替代确定性业务的workflow 也不适合独自维护很长的依赖链。
长任务最合适的是维护全局计划 在局部路径不确定的步骤中用react
