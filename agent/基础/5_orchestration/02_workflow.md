## 最小结构

workflow主要是需要回答 当前在做什么 结果存在哪里 接下来做什么。

所以最小结构为： node edge state entry/end

## Node

节点可以由模型、工具、规则、人工执行。

所以一个节点内部最好只做一件事 只产生一种可判断的结果。 **否则失败的情况 没办法定位失败 无法做到局部重试。**

拆分的粒度为 节点能否独立 执行 记录结果 和处理失败

并且可以用确定性规则完成的校验 不应该给模型 比如金额、schema、权限。

## Edge

核心作用是说明节点在什么结果下 进入哪个已注册节点 核心是 **路由** 作用



## State

state保存当前任务的权威执行事实。 并不是只是一个state状态字段。

state输入每个节点 每个节点应该可以明确从其中读取字段、写入字段、可能产生什么结果。

runtime才可以校验节点输入输出 并非让节点通过自然语言随意理解state。

所以state应该是**结构化字段** 自然语言摘要只是帮助模型理解 不可以代替权威状态。

### 区分 context memory

state是当前执行任务的权威执行事实。 他可能被送入llm节点 也可能被送入人工、规则节点。

memory是跨任务复用的长期信息。

context是本轮 llm节点 实际看到的消息。

runtime就是从state里选取决策必须的字段 放入llm。

任务结束后 state 一般会清理或者归档 其中少量具体长期可复用价值的信息 经过筛选后 可以进入memory。

## Entry-end

入口出口必须明确 特别是必须有终态。

节点没有报错 并不代表任务成功了。 只有目标完成、所有条件完成 才可以进入终态。
