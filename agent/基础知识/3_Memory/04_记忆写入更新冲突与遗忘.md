核心就是 记忆系统不是只会插入  **而是要管理信息从候选、确认、演化到失效的全过程。**

核心目标为： 该写入的准确写入 变化的正确更新 冲突的保留依据 失效的及时退出。

## 记忆写入流程：

原始信息
-> 提取候选记忆
-> 判断是否值得保存
-> 安全与权限检查
->  与已有记忆比较
-> 执行写入操作
-> 保存出处

所以候选记忆并不能直接落库

写入可以按明显事件触发，也可以在任务结束后批量提取，不一定每轮都调用模型抽取。


## 五种记忆操作

### append 新增
已有记忆中没有该事实，直接增加。

### update 原纪录发生变化
同一对象、同一属性，内容需要修改。 适用于可以原地维护的状态型事实。

### Supersede 新记忆取代旧记忆
旧记录曾经正确，但现在已经失效。不要直接抹掉历史，而应建立替代关系。

这样既可以使用新的事实 又保留变化历史

### Merge 合并
多条记忆含义相同或可以形成更完整的信息。

合并时必须保留原始出处，不能让总结生成不存在的新事实。

### Delete 删除

适用于：

- 用户明确要求忘记；
- 内容违法或不应保存；
- 数据超过保留期限；
- 记录被确认错误且无需保留；
- 账号或业务数据需要清除。



## 冲突处理

长期记忆中可能存在重复、过时和矛盾内容，例如：

不能仅依赖语义相似度，需要同时考虑：

- 记忆描述的实体和属性；
- 发生时间与有效时间；
- 信息来源；
- 用户是否明确纠正；
- 作用域是否相同

### 冲突处理顺序

1. **确认实体与属性**：避免把不同对象误判为冲突。
2. **检查作用域**：工作偏好与私人偏好可以不同。
3. **检查有效时间**：过去事实与当前事实可以同时成立。
4. **比较来源**：用户明确声明通常高于模型推断。
5. **选择操作**：并存、更新、替代或等待确认。

### 冲突无法判断的时候

不要擅自覆盖，应：

- 保留冲突状态；
- 暂时降低使用优先级；
- 在合适时向用户确认。### 去重

语义相近且含义相同的记忆可以合并，避免检索结果充满重复信息。

## 三个时间

事件时间： 事情的发生时间
写入时间： 记忆什么时候进入系统
有效时间：事实什么时候停止

判断事实优先看有效时间

## 去重 与 抽象提炼

### 去重

只有描述不同 但含义相同的时候合并 不能只使用向量相似度检索。 因为向量相似度会检索出来语义相反的信息。

### 抽象提炼

多个具体经历可以形成通用经验：
提炼原则：

- 有多个事实支持；
- 不超出原始证据；
- 保留来源；
- 原始经历不必立即删除。

> **总结只能压缩已有事实，不能创造新事实。**

## 遗忘机制

遗忘不是简单删除，而是让失效信息停止影响 Agent。

常见方式：

- **显式删除**：用户要求忘记；
- **有效期过期**：临时偏好到期；
- **替代失效**：新事实取代旧事实；
- **降低权重**：长期未使用、价值下降；
- **业务规则删除**：达到数据保留期限。


**为什么时间衰减不是通用遗忘方案？**

因为不同记忆的失效机制不同：临时偏好会自然过期，身份事实需要明确更新，审计信息可能依法长期保存。

**为什么不能直接采用“最新覆盖”？**

因为新旧信息可能属于不同实体、作用域或有效时间，也可能是低可信推断覆盖了用户明确事实。正确做法是结合实体、属性、作用域、时间和来源选择并存、更新或替代。
