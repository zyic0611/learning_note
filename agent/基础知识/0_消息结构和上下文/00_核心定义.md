消息结构的核心并不是要去理解有哪些消息 而是要知道

agent每次行动 都是在一段有顺序的上下文中 根据不同消息来源的 **权限 可信度 语义** 预测下一步应该输出什么。

系统可以抽象为：

上下文context 交给 llm 推理 然后assistant输出 是否调用工具 否则结束 是则tool call 得到tool result 然后再次循环


核心消息包括：
- system
- developer
- user
- assistant
- tool

消息就是作为提示词给llm看的 所以消息就是提示词 可以这么理解 但是消息可以是有选择的作为提示词

## 层级的控制协议

消息的本质不是聊天记录 是有层级的控制结构。 并不简单理解为 系统说的话 用户说的话 模型说的话。

每条消息至少包括四个维度
Message:
- role:消息角色
- context：消息内容
- position：在上下文中的位置
- trust/authority：可信度和指令优先级 对应层级控制。
