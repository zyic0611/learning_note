## 上下文构建span

记录
- context版本
- 提示词版本
- 输入消息数量
- 历史消息数量
- 工具定义数量
- context总token
- 截断前token、截断后token
- 是否压缩
- 是否使用缓存
- 构建耗时

context内容本身要谨慎记录  只能保存脱敏后的摘要、context引用、内容哈希等 概括性描述。

该span主要是回答 runtime给llm拼接了什么内容 是否发生截断、丢失or错误拼接 。


## 输入消息

模型收到的输入消息 一般不是一个字符串 而是一个消息数组 `message[]`
[
  {"role": "system", "content": "..."},
  {"role": "user", "content": "..."},
  {"role": "assistant", "content": "..."},
  {"role": "tool", "content": "..."}
]

所以需要记录发送进模型的消息有多少条 也就是记录runtime最后给模型拼接了多少内容 。
同一个问题失败了 就可以比较是不是输入消息数量的问题。 可能context的构建逻辑发生了变化

输入消息有一部分是来自于历史消息 。

## 截断

因为模型的上下文窗口有限 

上下文窗口要>=
- system prompt
- 历史对话
- 当前用户输入
- 工具定义
- 工具结果
- 预留输出空间
超过限制 就会做上下文压缩。

- 删除旧消息
- 压缩历史
- 截断工具调用结果
- 缩短prompt
