## 1 固定失败事实

先明确哪个run失败  什么成功条件没满足
evaluator是根据什么证据 判断失败
涉及哪些版本。

核心就是在发现任务失败的时候 固定这些条件 在后续排查的过程中 控制这些变量。

## 2 判断evaluator

因为错误是evaluator判定的 所以先要固定evaluator的判定是否正确

直接人工读取原始业务证据 人为判断 看是不是evaluator判定出问题 把对的证据 认为是错误的

## 3 还原失败trace

按照 **因果顺序** 聚焦于5点

- runtime构建了什么 context
- model 输出了什么
- runtime 如何解析model输出和路由
- tool 执行情况
- 最终业务状态

目的是找到失败链路实际发生了什么 不猜原因

## 4 对照正常trace 找到分支点

选择一条可以比较的trace 
- 相同任务类型
- 相似输入 不是相同 相似就可能还是错误结果
- 版本和环境尽量一直

然后按照因果顺序逐步比较 context model runtime tool

看分叉发生在哪里 定位的是最早发生问题的地点。

如果是版本退化 可以比较 新旧版本的trace。

## 5 提出假设并回放验证

找到第一个分叉点 只是根因假设 

然后根据假设 去做最小验证  就是控制变量 只修改分支点

任务成功 假设得到验证 任务失败 就向后排查
