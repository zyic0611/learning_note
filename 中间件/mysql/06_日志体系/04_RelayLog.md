Binlog 是主从复制的基石。而 Relay Log 则是从库（Slave）接盘的“中转站”。

- **它的作用**：存在于**从库**上。当主库的数据发生改变时，它会将主从同步的过程拆分成异步的两步，从而提升系统的稳定性和并发度。
    
- **主从复制的三步曲（结合 Binlog 与 Relay Log 面试必考）**：
    
    1. **主库的 Dump 线程**：当从库连接上来时，主库会开启一个 Dump 线程，负责把 Binlog 源源不断地发送给从库。
        
    2. **从库的 I/O 线程**：从库接收到主库传来的 Binlog 数据后，**并不立刻执行**，而是先把它顺序写入到本地的 **Relay Log（中继日志）** 里。
        
    3. **从库的 SQL 线程**：从库上的另一个专门的 SQL 线程，会不断地从 Relay Log 中读取日志并回放（执行），最终完成数据的同步。
        
- **为什么不直接执行，要引入 Relay Log 中转？**
    
    - 因为主库发数据是很快的网络 I/O，而从库回放 SQL 写入数据是较慢的磁盘 I/O（如果碰到大事务更慢）。如果从库 I/O 线程直接同步执行，一旦卡住，就会把主库的发送线程也阻塞。引入 Relay Log 就相当于加了一个**消息队列**，实现了接收和执行的解耦。   相当于先把命令全部塞给从库 网络io快。 从库在慢慢去执行 磁盘io慢。
