穿透实际上就是数据穿过redis层  直接到达mysql层。 通常是因为redis里查不到 就会去查db。

但是如果db没查到 数据就不会写入redis 所以针对这个key 每一次都会到达db。

一般是恶意攻击 疯狂请求不存在的key。

## 缓存空对象

当db返回null时候 缓存到redis里 设置一个很短的ttl 。

缺点：
内存消耗：如果每次都用不同的非法key发起请求 redis会缓存大量的空对象 k-v 浪费内存

数据短期不一致： 缓存null了 向db插入真实数据 则不会去更新缓存 在ttl前 数据不一致

## bloom filter
布隆过滤器本质上是一个**非常长的二进制位数组（Bit Array）**（初始全为 0）和**几个不同的哈希函数（Hash Functions）**。

```
判断一个数据存不存在 直接在java里用一个hashset存储所有ID不就行了吗？
不行 数据库有10亿1用户 则一个hashset就使用了几十GB的内存 oom
bloom filter解决了在海量数据下极快判断一个元素存在与否
```

1. 底层结构 采用 BitMap+**多个不同的Hash fuc**
2. 工作原理 存入一个id 10086
   - 用所有hash fuc 对10086进行计算
   - 得出n个结果
   - 在bitmap里把n个位置全部改成1
3. 拦截恶意请求
   - 请求先经过bloomfileter
   - n个hashfuc计算恶意id
   - 检查bitmap 只要一个是0 则id不存在 
   - 直接拦截 不会进redis和mysql
4. 误判率
   - **bitmap长度有限** 存入数据越多 1就越多 一个id刚好算出来的位置 由于存入数据很多 这几个位置由于其他正常id的映射 就污染成1 则误判。
1. 核心法则：你不存在肯定不存在 说你存在 你不一定存在
2. 缺陷：无法删除 如果删除一个数据 会修改正常数据的状态 一般不支持删除操作。要删除大批量数据，通常采用定期通过定时任务 把全亮数据库读取一次 重建一个bloom filter。 有误判率、 实现复杂。
3. 优点： 内存占用小
