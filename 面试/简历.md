### 项目一：智慧环卫招标分析平台（NL2SQL Agent）

**项目简介**：面向环卫招投标业务的数据分析 Agent，支持自然语言查数、多轮追问、趋势分析、企业竞争分析及日报/周报生成。

**核心技术栈**：Python、FastAPI、LangGraph、MySQL、Redis、SQLGlot、BM25 + Vector、SSE

**项目职责**：

- **多轮上下文理解与状态治理**：在主业务图前设计多轮上下文理解层，采用“规则判断、结构化意图相似度、低温度 LLM”**三级漏斗识别话题切换**，结合结果注册表完成跨轮**指代消解**和**追问类型识别**；基于强类型会话状态和字段级变更协议，统一处理时间、地域、指标、企业等槽位的继承、覆盖与清除，并输出**结构化上下文决策**，将请求路由至结果复用、重新查询或信息澄清流程，避免历史条件错误继承和跨话题状态污染。
    
- **语义规划与定向自修复**：设计结构化 **QueryPlan**，显式约束指标口径、统计维度、时间边界、过滤条件、关联路径及去重粒度；基于 **SQLGlot AST 语义一致性校验**识别生成 SQL 与查询计划的偏差，针对 Schema、指标口径、时间粒度和关联重复等错误分类注入修复上下文并执行限次重试，降低“SQL 可执行但业务结果错误”的风险。
    
- **Schema Linking 优化**：建设业务同义词、指标口径和表字段语义层，采用 **BM25 + Vector 混合检索**，叠加规则 Tag 强制召回与 QueryIntent 槽位增强，并通过 Join Graph 补全跨表关联路径；在固定金标集上，核心表与字段的样本级完整召回率由 **71% 提升至 95% 以上**，按需注入 Schema 上下文后，平均 Prompt Token 消耗降低 **17.3%**。
    
- **会话状态持久化与一致性**：基于 MySQL LangGraph Checkpoint 构建可恢复的会话状态存储，持久化 AgentState、结构化业务槽位、待澄清信息及执行进度；结合 **Redis 热点会话与查询结果缓存、结果引用及三级命名空间**，实现多实例状态共享、服务重启后的会话恢复及跨轮结果复用；针对同一会话的并发更新，引入**状态版本号、乐观锁和请求幂等机制**，避免状态覆盖与重复执行。改造后会话恢复成功率达到 **99.9%**，重复数据库查询减少 **65%**，结果型追问的 P95 响应时间降低 **70%**。
    
- **SQL 安全与成本治理**：构建基于 SQLGlot AST 的多层 SQL 治理链路，实现只读语句校验、表白名单、危险操作拦截及 LIMIT 策略注入；结合**规则化风险评分与 EXPLAIN 扫描行数评估**，并通过执行超时和数据库只读权限兜底，在查询执行前拦截高风险、高成本 SQL。
    
- **LLM 服务稳定性治理**：构建 LLM 调用异常分类、指数退避与随机抖动重试、**失败率熔断及半开探测机制**，结合连接、读取、请求级超时和全链路重试预算，避免模型服务抖动引发重试风暴与故障级联；为 SSE 流式链路增加**心跳保活、总时长控制和客户端断连取消**，提升长耗时 Agent 任务的可用性与资源回收能力。
    

### 项目二：城市应急环卫调度平台（Java）

**项目简介**：面向暴雨防汛、大型活动等突发场景的环卫调度平台，负责应急工单发布与高并发抢单链路设计。

**核心技术栈**：Spring Boot、MySQL、Redis、RabbitMQ

**项目职责**：
- **高并发抢单优化**：将资格校验、名额扣减和重复提交校验前置至 Redis，通过 Lua 保证校验与扣减的原子性，并以 MySQL 唯一索引保障最终幂等；在相同压测环境和 200 并发下，核心接口吞吐量由 474 QPS 提升至 886 QPS，压测期间未出现超卖。
    
- **异步削峰与性能优化**：采用 RabbitMQ 解耦请求受理与数据库落库，Redis 预扣成功后异步持久化，降低应用线程池及数据库连接池压力；相同测试条件下接口吞吐量进一步提升至 1123 QPS，P99 为 375ms，接口无 5xx 及连接池超时，压测结束后消息均完成消费。
    
- **消息可靠性与数据一致性**：通过 Publisher Confirm、手动 ACK、死信重试和 Outbox 补发保障消息可靠性，并利用唯一索引及业务幂等键防止重复落库；通过定时对账任务比对 Redis 预扣结果与 MySQL 落库记录，对异常消息进行补发或库存回补，故障演练中未产生重复业务记录，异常数据可在一个对账周期内完成修复。
