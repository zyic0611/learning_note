实际企业级开发中 拒绝使用 Executors工具类 适用自己定 ThreadPoolExecutor是标准且安全的做法。

## OOM风险

原因是在底层把线程池的7个参数写死了 有OOM风险

固定的线程池方法用的是,容量为 Integer.Max_Value的 LinkedBlockingQueue无界队列 如果涌入海量任务 由于核心线程数四固定的 剩下所有任务都会堆积在阻塞队列中 耗尽服务器内存 导致OOM。

内置的缓存线程池方法 最大线程数 设置为了Integer.Max_Value 业务很耗时 并且并发量大 线程池会无线创建大量临时线程 会导致CPU频繁切换上下文 



## 原则

日常开发坚守原则：

1.显示声明7个参数 用new ThreadPoolExecutor方式构建线程池

2.坚持使用有界队列 公主哦队列必须显示制定容量 使用数组的 或者制定容量的链表的

3.定制拒绝兜底策略 为业务定制 防止业务线被拖垮。
