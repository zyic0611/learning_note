
## 1. Java 对象在堆内存中的布局结构

对象由三部分组成：

- **对象头**
  - Mark Word（8字节）：存 hashcode、GC年龄、锁状态
  - Klass Pointer（类型指针）：指向方法区的类元数据
  - 数组长度（仅数组对象，4字节）
- **实例数据**：各字段值
- **对齐填充**：补齐到 8 字节整数倍

---

## 2. synchronized 锁升级过程

无锁 → 偏向锁 → 轻量级锁 → 重量级锁（不可逆）

| 状态 | Mark Word 内容 | 低2位 |
|------|--------------|-------|
| 无锁 | hashcode + GC年龄 | 01 |
| 偏向锁 | 线程ID + epoch | 01（偏向位=1）|
| 轻量级锁 | 指向栈帧 Lock Record 的指针 | 00 |
| 重量级锁 | 指向堆中 ObjectMonitor 的指针 | 10 |

- **偏向锁**：Mark Word 记录线程ID，同一线程重入无需 CAS
- **轻量级锁**：线程在栈帧创建 Lock Record，CAS 替换 Mark Word；失败则自旋
- **重量级锁**：自旋超限，升级为 ObjectMonitor；阻塞线程，涉及内核态切换
- ObjectMonitor 包含：`_owner`（持锁线程）、`_EntryList`（BLOCKED队列）、`_WaitSet`（WAITING队列）

---

## 3. Minor GC 和 Full GC 触发条件

**Minor GC**：Eden 区满

**Full GC 触发原因：**
1. 老年代空间不足
2. 空间分配担保失败（老年代剩余 < 历次晋升平均大小）
3. 大对象直接进老年代，老年代放不下
4. 元空间不足
5. 显式调用 `System.gc()`

---

## 4. Stop-The-World（STW）

**STW**：暂停所有用户线程，等待所有线程到达安全点后执行全局操作（如GC）。

以 CMS 为例，STW 发生两次：
- **初始标记**：标记 GC Roots 直接可达对象
- **重新标记**：修正并发标记期间因用户线程运行导致的引用变化（漏标）

**安全点（Safepoint）**：线程主动检查标志并挂起自己的位置（方法调用、循环回边、异常抛出处）。STW 不是强制冻结，而是等所有线程走到安全点后才生效。

---

## 5. 双亲委派机制

类加载时优先委托父级加载器，父级无法加载才自己加载。

**为什么：**
- 避免重复加载（同一个类只加载一次）
- 安全性（无法用自定义类替换 `java.lang.String` 等核心类）

**打破双亲委派的场景：**
| 场景 | 手段 |
|------|------|
| SPI（JDBC） | 线程上下文类加载器，Bootstrap 向下委托 AppClassLoader |
| Tomcat | 自定义 ClassLoader，优先加载 WebApp 自身类，实现版本隔离 |
| OSGi | 网状类加载，彻底抛弃树形结构 |

## 6. volatile 关键字

**保证两点：可见性 + 有序性（禁止指令重排）**

- **可见性**：写操作立刻刷回主内存，其他线程缓存失效，强制读主内存
- **有序性**：读写前后插入内存屏障，防止指令重排；经典场景：双重检查锁单例必须加 volatile

**不保证原子性**：`i++` 是读-改-写三步，volatile 无法保证。需用 `synchronized` 或 `AtomicInteger`。

---

## 7. G1 垃圾回收器

**特点：**
- 堆划分为等大小的 **Region**，逻辑上保留新老生代概念
- **H 区（Humongous）**：存放超过 Region 大小一半的大对象
- 可设置目标停顿时间（`-XX:MaxGCPauseMillis`）
- 优先回收垃圾最多的 Region（Garbage First）
- 标记-复制算法，**无内存碎片**
- **Mixed GC**：同时回收新生代 + 部分老年代 Region

**vs CMS：**
| | CMS | G1 |
|--|-----|----|
| 算法 | 标记-清除（有碎片） | 标记-复制（无碎片） |
| 停顿时间 | 不可控 | 可设置目标 |
| 回收范围 | 只有老年代 | 新生代 + 老年代 |
| 并发失败 | 有 Concurrent Mode Failure | 较低 |

---

## 8. 类加载过程

**加载 → 链接（验证→准备→解析）→ 初始化**

1. **加载**：读取 .class 字节流，转为方法区运行时数据结构，堆中创建 `Class` 对象
2. **验证**：校验字节流格式、元数据、字节码合法性
3. **准备**：为静态变量分配内存并赋零值；`static final` 常量直接赋真实值
4. **解析**：符号引用 → 直接引用
5. **初始化**：执行 `<clinit>` 方法（静态代码块 + 静态变量赋值）；JVM 保证 `<clinit>` 线程安全

---

## 9. 对象进入老年代的场景

1. Survivor 区存活超过年龄阈值（默认 **15次**，`-XX:MaxTenuringThreshold`）
2. 大对象直接分配到老年代（超过 `-XX:PretenureSizeThreshold`）
3. **动态年龄判断**：Survivor 区同龄对象总大小超过 Survivor 空间一半，直接晋升
4. **Survivor 溢出**：Minor GC 后存活对象放不进 Survivor，溢出到老年代

## 10. happens-before 原则

**定义**：操作 A happens-before 操作 B，则 A 的结果对 B 可见，且 A 在 B 之前执行。

JMM 在"允许优化"和"保证正确性"之间划的边界线。

**六条核心规则：**
| 规则 | 含义 |
|------|------|
| 程序顺序规则 | 同一线程内，前面操作 hb 后面操作 |
| volatile 规则 | volatile 写 hb 后续 volatile 读 |
| 监视器锁规则 | unlock hb 后续对同一锁的 lock |
| 线程启动规则 | `Thread.start()` hb 该线程的所有操作 |
| 线程终止规则 | 线程所有操作 hb `Thread.join()` 返回 |
| 传递性 | A hb B，B hb C，则 A hb C |

## 11. JIT 编译器

Java 是半解释半编译语言：
- **解释执行**：逐行解释字节码为机器指令，灵活但慢
- **JIT 编译**：热点代码编译为本地机器码缓存，后续直接执行，跳过解释

**热点探测：**
- 方法调用计数器（方法调用次数超阈值）
- 回边计数器（循环次数超阈值）

**两个编译器（分层编译）：**
- **C1**：编译快，优化少，快速启动
- **C2**：编译慢，优化激进，长期运行性能高

## 12. CMS 垃圾回收器

**四个阶段：**
1. **初始标记（STW）**：标记 GC Roots 直接可达对象
2. **并发标记**：不 STW，遍历完整引用链
3. **重新标记（STW）**：处理并发标记期间 Write Barrier 记录的引用变化，防止漏标
4. **并发清除**：不 STW，标记-清除算法回收垃圾

**缺点：**
| 缺点 | 说明 |
|------|------|
| 内存碎片 | 标记-清除天然产生 |
| 浮动垃圾 | 并发阶段新产生的垃圾本轮无法回收，需预留空间（默认92%触发） |
| Concurrent Mode Failure | 老年代在并发期间被填满，退化为 Serial Old，STW 时间极长 |
| CPU 竞争 | 并发阶段与用户线程抢 CPU |

---

## 13. OOM 发生区域

| 区域 | 异常信息 | 触发方式 |
|------|---------|---------|
| 堆 | `Java heap space` | 对象太多，GC 后仍放不下 |
| 元空间 | `Metaspace` | 动态生成大量类（CGLib/JSP）撑满元空间 |
| 虚拟机栈 | `unable to create new native thread` | 创建线程过多 |
| 直接内存 | `Direct buffer memory` | NIO `ByteBuffer.allocateDirect()` 超限 |

> 注意：递归太深是 `StackOverflowError`，不是 OOM。

---

## 14. GC Roots

- 虚拟机栈帧局部变量表中的对象引用
- 本地方法栈 JNI 引用的对象
- 方法区类静态属性引用的对象
- 方法区常量池引用的对象
- 活跃线程
- synchronized 持有的对象

**为什么能作为 GC Root**：生命周期由 JVM/OS 直接管控，是"确定存活"的起点。

---

## 15. 对象创建过程（new 关键字）

1. **类加载检查**：确认类已加载、链接、初始化
2. **分配内存**：指针碰撞（整齐堆）或空闲列表（碎片堆）；优先在 **TLAB**（线程私有缓冲区）分配，避免加锁
3. **初始化零值**：所有字段置为默认值（这就是 Java 字段不用手动初始化的原因）
4. **设置对象头**：Mark Word、Klass Pointer
5. **执行 `<init>`**：构造方法赋实际值

---

## 16. 逃逸分析

JVM 分析对象是否会"逃出"当前方法或线程。不逃逸则可做三种优化：

1. **标量替换**：对象拆散为基本类型字段，分配在栈上，不创建对象（最常用）
2. **栈上分配**：整体对象分配在栈帧，方法退出自动回收
3. **锁消除**：对象不会被多线程访问，`synchronized` 直接去掉

---

## 17. 方法区（JDK 7 vs JDK 8）

| 内容 | JDK 6 | JDK 7 | JDK 8 |
|------|-------|-------|-------|
| 类元数据 | 永久代 | 永久代 | 元空间（本地内存）|
| 运行时常量池 | 永久代 | 永久代 | 元空间（本地内存）|
| 字符串常量池 | 永久代 | **堆** | 堆 |
| 静态变量 | 永久代 | **堆** | 堆 |

**为什么换元空间**：永久代有固定大小上限（`-XX:MaxPermSize`），频繁 OOM；元空间用本地内存，默认无硬性上限。

---

## 18. JMM 主内存与工作内存

- **主内存**：所有线程共享，存储变量的"真实值"
- **工作内存**：每个线程私有，对应 CPU 缓存和寄存器的抽象

**线程通信过程**：
1. 线程 A 将工作内存中的值写回主内存
2. 线程 B 从主内存读取最新值到工作内存

`volatile` 和 `synchronized` 强制执行这两步，保证可见性。

## 薄弱点汇总

| 薄弱项 | 要点 |
|--------|------|
| 对象内存布局 | Mark Word 存锁状态/hashcode/GC年龄 |
| OOM区域 | 栈OOM是线程太多，不是递归 |
| Minor GC 触发 | 只有 Eden 区满，不含 S 区 |
| Full GC 原因 | 共5种，分配担保失败是高频考点 |
| volatile | 只保证可见性+有序性，不保证原子性 |
| 对象创建 | 第一步是类加载检查；TLAB 避免堆分配竞争 |
