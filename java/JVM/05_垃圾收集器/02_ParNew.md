全称是 Parallel New Generation

ParNew 可以理解为 Serial 收集器的多线程版本。两者在新生代都采用复制算法，回收流程基本一致，区别在于 ParNew 在 Minor GC 时使用多条 GC 线程并行完成对象扫描、复制和晋升。

## PLAB机制

是并发安全的核心底层。

多线程并发将新生代存活的对象复制到 **Survivor 区** 或**晋升到老年代**，那么多条 GC 线程同时向一块内存区域写入对象时，如何保证不发生内存覆盖（即指针碰撞时的并发安全问题

**初级解法**：加锁。用mutex lock或者每次分配内存时使用 **CAS** 配合自旋。但这会引发极其严重的锁竞争，拖垮多线程并行的效率。

**HotSpot 实现**：ParNew 引入了 **PLAB (Promotion Local Allocation Buffer，晋升本地分配缓冲区)** 机制。在垃圾回收开始时，每条 GC 线程会提前向 **Survivor 区或老年代**申请一块专属的、独立的内存块（即 PLAB）。所以PLAB在新生代和老年代里都有

**执行逻辑**：当 GC 线程需要复制存活对象时，优先分配在自己的 PLAB 中，这个过程是绝对线程安全的，无需任何加锁操作（无锁分配）。只有当专属的 PLAB 用尽，需要申请新的 PLAB 时，才需要通过 CAS 操作进行同步。这种设计极大地降低了锁竞争，榨干了多线程的吞吐量



## 存在的原因 配合CMS

既然有了设计更优秀、专注吞吐量的 **Parallel Scavenge 收集器**（也是新生代多线程），为什么还要保留 ParNew

Parallel Scavenge 与 CMS 的设计目标和内部实现不同，HotSpot 从未实现两者之间的协同工作，因此 CMS 在新生代只能搭配 ParNew。

## 线程调度策略与单核陷阱

多线程并不是一定比单线程快 默认情况下，ParNew 开启的收集线程数与 CPU 的核心数量相同

## 总结
ParNew 本身没有任何算法创新，它最大的价值在于把 Serial 的复制算法改造成多线程实现，并通过 PLAB 解决了多线程对象复制时的分配竞争，从而成为 CMS 唯一可搭配的新生代收集器。
