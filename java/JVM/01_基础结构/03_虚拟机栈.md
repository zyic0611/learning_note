java虚拟机栈是线程私有的 生命周期与线程完全一致 每启动一个新线程 JVM就会分配一个对应的虚拟机栈。 里主要存储的是线程执行的方法

物理模型是 **栈帧模型 Stack Frame：**

虚拟机栈描述的是 **java方法执行** 的内存模型。 线程中每一次方法的调用到执行完成 都对应的一个 栈帧在虚拟机栈 push 和 pop过程。 当前正在执行的方法对应的栈帧为当前栈帧

栈帧由4大核心部分组成。

## 局部变量表 

是一组 变量值的存储空间 用于存放 **方法参数** 和 方法内部定义的 **局部变量**。是很多slot 。

### Slot

存储单元为 变量槽 Slot ：局部变量表的容量以变量槽为最小单位。 

JVM规定一个 Slot可以存放**32位**以内的数据类型 比如 boolean byte char short int float reference returnAddress 

64位的long 和 double 虚拟机会用高位对其的方式 分配两个连续的Slot

### Slot 复用与GC

为了解决栈空间 Slot可以被**重复利用**。 当指令的执行已经超出了某个变量的作用域 该变量对应的slot就可以被其他方法的变量重用。

slot复用可能影响 GC：

如果一个占用大量内存的对象的作用域已经结束了 但是在方法内部仍然有耗时操作 导致没有发生Slot覆盖 那么作为GC Roots一部分的局部变量表为依然保持对该对象的引用 导致无法被回收。   个人理解：就是一个方法 内部有一个很大的对象 对象的作用域已经结束了 其实已经可以释放了 但是方法还没结束 方法对应的栈帧 里面的局部变量表 还保持的对这个对象的引用 无法回收

大厂标准优化方式： 作用域结束后 不等方法结束 立刻手动将对该大对象的引用设置为null 帮助解除强引用，

### this 关键字

如果执行的是实例方法 非static方法。 局部变量表的第0位索引 也就是Slot0 默认用于传递方法所属对象实例的引用。 这也是在方法内部可以使用this的底层原因。



## 操作数栈

是一个栈结构 后入先出 LIFO 用于在方法执行过程中 充当计算的临时数据交换区。

**基于栈的执行引擎：**

​	与x86架构中 基于 寄存器的 物理CPU不同 JVM的解释执行引擎是基于栈的。绝大多数字节码指令都是对操作数栈进行push和pop

**举例说明**：

​	例如执行简单的加法 `a + b`。底层的字节码逻辑是：先使用 `iload` 指令将局部变量表中的 `a` 和 `b` 复制到操作数栈的栈顶；然后使用 `iadd` 指令将栈顶的两个元素弹出（Pop）并相加；最后将相加的结果重新压入操作数栈（Push）；最终通过 `istore` 指令将结果从操作数栈弹回局部变量表中。

## 动态链接

每个栈帧都包含一个指向 **运行时常量池（）** 中 该栈帧 所属于的方法 的引用。  持有这个引用是为了支持方法调用过程中的 动态链接。

- 当java源文件 被编译为class文件时候 所有的变量和方法引用 都作为符号引用 保存在Class文件的常量池中。 此时是编译期 数据为静态。
- 在类的生命周期链接期间的解析阶段 会把可以确定的符号引用直接转换为直接引用。
- 剩下不能确定的，当程序运行到具体的调用指令的时候 虚拟机会将这些符号引用转化为指向实际内存地址的直接引用。  此时是运行期 符号引用需要被转换
- 如果每一次运行期间都在动态转换为直接引用 过程就叫动态链接。 
- 支持了Java的多态和晚期绑定

## 方法返回地址

方法退出的条件：

**正常完成出口：** 遇到方法返回的字节码指令 比如return ireturn areturn 此时会把返回值压入调用者（上层栈帧）的操作数栈中 并且根据PC寄存器保存的返回地址 恢复调用者的状态

**异常完成出口：** 遇到了异常 并且没在方法体中被捕获 也就是异常表没匹配 此时不会给上层调用者任何返回值
