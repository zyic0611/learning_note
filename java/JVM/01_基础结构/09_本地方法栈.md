## 物理本质

本质上作用和java虚拟机栈发挥的作用类似 关键区别在于服务对象不同

- 虚拟机栈：为 JVM执行java方法 即字节码服务

- 本地方法栈：为JVM使用到的 Native方法 一般由C/C++便携 直接与OS或者底层硬件交互的方法服务

**生命周期** 是线程私有的

## HotSpot的设计

在HotSpot虚拟机中 本地方法栈和虚拟机栈合二为一

**底层原理：**

JVM 规范允许各家虚拟机厂商自由实现本地方法栈。由于 HotSpot 内部大量使用了 C/C++ 代码来实现虚拟机的核心功能，并且其 JIT（即时编译器）会在运行时将 Java 字节码编译为本地机器码执行，为了降低架构复杂度和避免维护两个独立栈带来的性能损耗，HotSpot 的工程师直接将虚拟机栈和本地方法栈合并为了一个栈。

**参数控制：**

因此虚拟机栈的容量 同时控制了 java方法和native方法运行时的栈深度 如果执行Native方法期间 栈空间不足 会跑出

StackOverflowError 或者 OOM
