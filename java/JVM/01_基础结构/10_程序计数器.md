程序计数器： Program Counter Register

## 本质

是一块很小的内存空间。

在硬件层面：物理CPU中的PC 用于指示下一条需要执行的物理指令

在JVM的抽象内存模型中 是设计为一个 **字节码行号指示器** 由JVM的执行引擎负责在软件层面动态维护和更新 空啧啧 分支、循环、跳转等基础运行逻辑。

## JUC高并发下的上下文切换

在高并发情况下 底层的CPU核心 会通过时间片轮转机制 在成百上千个竞争线程之间进行极速切换

当一个执行的线程因时间片耗尽 争抢锁失败 或遇到I/O阻塞 被操作系统强制挂起的时候 JVM就必须精准记录该线程当前执行到哪一行字节码。 

该任务完全依赖于PC计数器。 线程如果后续被唤醒重新获取CPU调度的时候 JVM就会直接读取PC计数器里保存的值 实现指令级别无缝状态恢复

## OOM净土

是唯一一块没有任何OOM的区域。 

因为其的存储需求是静态且固定的 不管业务方法内部逻辑结果多么庞大 或者嵌套调用的层级有多么深 程序计数器永远只需要保存一个固定长度的内存地址 Return Address
