当执行 `User user=new User()` 创建了一个对象

内部执行的流程为：

1. 类加载检查
2. 分配对象内存
3. 初始化0值
4. 设置对象头
5. 执行构造方法
6. 对象创建完成

这里都是普通的对象创建流程

**数组 Class对象 STring常量池**对象 会有特殊处理。

## 类加载检查

jvm 看到 new User 需要先判断 User这个类有没有被加载到JVM中 

因为JVM执行代码 本质上自信的是 .class字节码文件 并非源代码

.java文件先被 编译为 .class文件 

JVM运行 通过classLoader加载 user.class 生成 class对象 存入方法区 

所以User类没有加载的话 JVM就会触发类加载机制

## 类加载过程 

并不只是简单的读取 .class 字节码文件。

完整过程是 加载 链接（验证 准备 解析）初始化

加载阶段和对象创建关系最大： 

主要公主哦是把class文件的加载到JVM 会在JVM内部生成Class对象 代表 User这个类本身  不是对象 是类。

User的实例对象放在堆里面。 User类的信息放在方法区里

## 类初始化问题

类加载 并不等于 类初始化

```java
class User {

    static int count = 10;

}
```

静态变量 count=10 是在类加载过程的 初始化阶段完成的 。

初始化阶段的任务就是 为类的静态变量等 属于类的属性分配值。

初始化阶段会执行 `<clinit>()` JVM会生成 static代码块 + 给static变量赋值。

**创建对象 一定会导致类加载 但是不一定都会类初始化 类只会初始化一次**

## 类初始化的触发

**new对象** 会触发 类的加载 + 类的初始化

**访问静态变量** 当访问类的静态属性变量的时候 如果不是常量 就会触发初始化

**调用静态方法** 

**反射** `Class.forName("User");` 默认触发初始化

**特殊 类的常量的调用不会触发初始化  因为编译阶段 会把常量 放入调用类常量池 其实完全不需要User类** `System.out.println(User.AGE);=System.out.println(18);`
