初始化0值  是JVM给刚分配的内存实例 进行0值初始化字段值。



## 是什么

一个拥有字段的对象 刚被new方法创建出来。

如果本身没有写构造函数  那么此时访问该对象的字段 就会是默认值 0 null false等等。

JVM把 

数值类型 比如short int long float double 等 默认为0

字符串类型 默认为 `\u00000`

引用类型为 nuull

布尔类型为false

## 发生位置

对象创建流程中： ` new User()-- 类加载检查--分配内存--初始化0值--设置对象头--执行构造方法--对象创建完成`

所以初始化0值 是发生在构造方法执行之前。 分配内存之后。

 所以构造方法 并不是第一次去初始化对象 而是发生在JVM默认0值初始化后 才进行业务初始化

## 原因

是为了保证java内存安全模型 

C++ 中  如果不对类字段进行初始化 可能会输出随机垃圾值 因为堆内存以前可能存在过其他数据。

java不允许 java要求 任何对象的字段在访问之前 必须拥有确定的初始值。 

## 解决

防止读取未初始化变量   输出堆里面的旧数据

保证对象状态确定 保证初始状态都是false之类的

## 与成员变量默认值

java成员变量 有默认值 其实是因为 JVM对象创建流程中的0值初始化。 

允许在类中

 `int age;`

`System.out.println(age);` 

因为JVM已经初始化了成员变量



### 局部变量

比如

```java
public void test(){

    int age;

    System.out.println(age);

}
```

就会报错 

因为局部变量 存在栈帧里

JVM不会自动去清0 必须程序员手动赋值 显式赋值为 0 

int age = 0  。



## 总结

为什么要0值初始化

JVM在对象分配内存后，会对对象实例数据区域进行零值初始化，保证对象字段在执行构造方法之前已经具有确定的默认值。这是Java安全模型的一部分，可以避免读取未初始化内存带来的不确定行为，同时保证成员变量具有语言规范定义的默认值。
