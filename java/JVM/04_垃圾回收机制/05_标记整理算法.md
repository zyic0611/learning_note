复制算法在对象存活率较高时，会产生大量的复制开销，且需要额外的空间进行担保。老年代对象存活率极高，且没有额外空间为其进行担保，因此必须使用“标记-整理”算法。

## 核心指标：
- 空间利用率: 100%
- 产生内存碎片：否 
- 内存分配方式：使用**指针碰撞**  直接往空闲的空间分配内存 分配很高
- 执行开销： 整理阶段需要大范围移动对象 并更新引用 **STW停顿最长**
- 适用场景： 老年代 **存活率很高** 追求吞吐量 或者作为CMS的兜底


**深度理解：吞吐量优先的取舍**
- **内存压缩**：标记过程与“标记-清除”一样，但后续步骤不是直接清理，而是让所有存活的对象都向内存空间一端滑动移动，然后直接清理掉边界以外的内存。
    
- **指针更新与 STW**：移动存活对象是一项极具负担的操作。在移动对象后，必须更新所有指向这些对象的引用 比如B被移动了 修改A->B。在 HotSpot 的传统实现中，**这种引用的更新必须在全程 STW 的状态下进行。**
    
- **分配效率 vs 收集延迟**：虽然移动对象会导致较长的 STW（延迟较高），但由于内存变得绝对连续，后续的对象分配可以通过极其高效的**指针碰撞** 来完成（无需维护复杂的空闲列表）。**Parallel Old** 收集器正是基于此算法，用以追求吞吐量的最大化

## 任意顺序算法 双指针算法
最早的 最简单的整理算法 不要求保留对象的原有顺序 主要用于 **固定大小** 的对象内存块。 

1. **初始化**：设置两个指针，**左指针 (Free Pointer)** 指向堆的起始端，**右指针 (Live Pointer)** 指向堆的末尾端。
    
2. **对调移动**：左指针向右扫描，寻找首个**死对象**；右指针向左扫描，寻找首个**活对象 **。
    
3. **复制与记录**：将右指针指向的活对象复制到左指针的空闲位置，并在原活对象的旧内存地址处留下一个**转发地址** 指向新位置。
    
4. **循环直到碰撞**：重复此过程，直到两个指针相遇，此时相遇点右侧全部变为连续的空闲内存。
    
5. **更新引用**：再次遍历整个堆或通过 OopMap 遍历 **GC Roots**，将所有指向旧地址的指针根据留在原处的转发地址更新为新地址。
理解为就是双指针遍历 左边死的位置 就把右边活的换进去 最后保证左边只要被占用的都是存活 右边都是空闲的

**缺陷**
由于打乱了对象的内存物理顺序，会严重破坏程序的**空间局部性** 导致 CPU 缓存命中率下降；且无法直接处理变长对象。 因为变长对象需要分配的空间未知

### 滑动整理算法 Lisp2算法
现代JVM都是采用滑动整理算法。即在移动活对象时，必须保证它们在内存中的相对顺序与整理前完全一致，以维护极佳的缓存局部性。 

Lisp 2 算法的实现极为严谨，它通过**三次完整遍历** 堆内存来完成整理工作。 本质上是 先计算 再更新别人的引用 最后真正移动
- **第一遍扫描：计算并记录新地址**
    
    - 设置一个扫描指针从**堆底向堆顶**扫描。
        
    - 每当扫描到一个活对象，根据它前面已经累计的活对象总体积，计算出它滑动整理后应当所处的**目标新地址**。
        
    - 将这个目标新地址直接写入该对象的**对象头** 的 Mark Word 中（临时覆盖原有的哈希码或锁信息）。
        
- **第二遍扫描：更新全局引用 (Update References)**
    
    - 遍历所有的 GC Roots 以及堆中所有活对象内部的引用域。
        
    - 检查每个引用指针指向的旧对象，读取该旧对象头中记录的“目标新地址”，然后将当前引用指针直接修改为该新地址。**此时，对象还未真正移动，但所有的指针已经提前指向了未来的新位置。**
        
- **第三遍扫描：实际移动对象 (Move Objects)**
    
    - 再次从堆底向堆顶遍历。
        
    - 将每个活对象的数据（包含其真实的字段数据）物理复制到它对象头里记录的“目标新地址”中，随后将对象头复原。
        
    - 此时，相连的活对象被紧密排列在堆的一端，边界之外的剩余空间被彻底释放，形成完全连续的内存。
    - 相对顺序不变

## parallel old 的Region整理算法

HotSpot 的 **Parallel Old** 收集器中，为了提升多线程并行整理的效率，并没有采用单线程的 Lisp 2 算法，而是采用了**基于区域** 的滑动整理策略

1. **划分 Region：** 老年代被划分为大小固定的 **Region**（通常为几百 KB 到几 MB）。 与G1的Region不同，标准的叫Compact Region 压缩区域
2. **标记与统计：** 并行标记所有活对象。在标记的同时，收集器会统计每个 Region 内部的对象存活数量
3. **划分密集区与收集区：** 根据统计数据，计算出一个**密集点**。密集点左侧的 Region 活对象极多，移动它们的成本远高于收益，因此这些 Region 被视为“不移动区”；密集点右侧的 Region 活对象较少，被划分为“收集区”，其内部的活对象将被集中滑动迁移到左侧的空闲插槽中。
4. **紧凑移动：** **多个 GC 线程**并行并发地将右侧 Region 里面的的活对象跨 Region 滑动到左侧的Region，并批量更新引用指针。由于划分了独立的 Region，**不同的线程**可以独立负责不同区域的移动与重定向，极大地缩减了传统标记-整理算法中长达数秒的 **STW** 停顿。
