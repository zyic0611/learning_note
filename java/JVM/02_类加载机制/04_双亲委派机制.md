双亲委派模型并不是一个强制性的约束模型，而是 Java 设计者推荐给开发者的类加载器实现方式。

## 工作原理

当一个类加载器收到加载类的请求时，它首先不会自己尝试去加载，而是把这个请求委派给父类加载器去完成，每一层都是如此。其核心逻辑完全固化在 `java.lang.ClassLoader` 的 **`loadClass()`** 方法中：

## 核心价值

1. **沙箱安全机制** 防止核心 API 被用户恶意篡改或替换。在双亲委派机制下 就算恶意开发者在工程里编写了一个string类 加载请求最终也会到达启动类加载器 优先加载jdk自带的string类 不会加载自定义的恶意代码
2. **类实例的唯一性**：JVM 中判断两个类是否相等，不仅要求类全限定名相同，还要求**加载它们的类加载器是同一个**。双亲委派确保了基础类在各种类加载器环境中都是同一个 `Class` 对象。
