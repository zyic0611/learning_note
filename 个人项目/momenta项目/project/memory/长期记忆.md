# 长期记忆(跨会话)

## 一句话定义

从关闭的线程里**异步提取原子记忆条目**,按 user/group/global 隔离存储,对话开场时按提问者召回。存入的是"一句话的原子事实",不是线程摘要。

---

## 存的两类

| 类型 | 是什么 | 例子 |
|---|---|---|
| 语义记忆 | 事实 / 偏好 | "张工项目是域控X电源板,需求3.3V/5A" |
| 情景记忆 | 某次过程 + 结论 | "0903完成降压选型:TPS54331(国产+库存)" |

(别叫"程序性记忆"——那是"做事技能"的意思,面试官较真会被抓)

---

## 完整流程(背诵版)

```
触发
├─ 线程归档(主,超24h无复活)
├─ 长线程中途(超50条/2h,增量提取)
└─ 显式触发("记住这个")
        │
        ▼
离线提取(小模型):digest + 关键原文 → 原子条目数组
  每条:{类型, scope, 主体, 实体, 内容(一句话), 重要性, 持久度}
        │
        ▼
重要性过滤:低分候选直接扔 —— 垃圾别让它成为候选
        │
        ▼
去重与冲突(永远不"全量",三段收窄):
  ① 结构化键精确查(user + 实体 + 属性)→ 只对命中的少数条裁定
  ② 未命中 → ANN top-k(同 scope,HNSW 索引,只看 3~5 条):
        > 0.9   → 规则直接更新旧条(新胜旧、软删、留审计)
        0.7~0.9 → 强模型 LLM 裁定:更新 / 合并 / 新增
        < 0.7   → 新增
        │
        ▼
写库:PostgreSQL,JSONB(结构化过滤)+ pgvector(向量召回)双存
        │
        ▼
存量修剪:
  · 单用户条数上限(如200)→ 按 重要性×被召回次数×时间衰减 淘汰末位
  · 冷条目:last_accessed 长期未被召回 → 衰减降级软删
```

---


 **模型分档**:提取用**小模型**(量大、错误能被过滤去重兜住);0.7~0.9 裁定用**强模型**(量小、判错会污染之后每次回答)。背:"提取靠便宜走量,裁决靠贵保准。"

---

## 一条边界

- 窗口内的"接着问" → 会话记忆**复活**(上下文连贯)
- 窗口外的"上次聊的" → 长期记忆**召回**(摘要级结论)
- 两个系统在时间窗口上划界。

---

## 口播版(约 45 秒)

> 长期记忆存两类东西:语义记忆是事实和偏好,情景记忆是某次讨论的过程和结论。写入口径是异步的:线程归档时、长线程中途、或用户说"记住这个",离线用一个小模型对线程摘要加关键原文做结构化提取,输出原子条目——一条记忆必须一句话成立、有跨会话价值,过程性问答和寒暄在这个环节就被重要性过滤扔掉了。
> 去重冲突这步永远不做全量比对:先用结构化键精确查同一主体同一属性的旧条目,查不到再走向量 top-k,相似度九成以上规则直接更新,七到九成交给强模型裁定,低于七成新增,新胜旧、旧条软删留审计。最后存量有两条修剪:条数上限按重要性乘被召回次数乘时间衰减淘汰,长期没被用过的冷条目降级。
> 和会话记忆的边界:窗口内的接着问走复活,窗口外的走召回。两条线的资产是分开的。
