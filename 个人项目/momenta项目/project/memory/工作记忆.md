# 工作记忆(执行态)

## 一句话定义

一次任务从**规划完成到聚合结束**的执行账本,任务级临时状态容器。LeadAgent 的拆解只是**第一章**,不是全部。

---

## 存的什么

| 内容 | 例子 |
|---|---|
| LeadAgent 拆出的 **DAG 节点状态图** | A 查器件库 `succeeded`、B 选型推荐 `running`、C 测试方案 `pending`(依赖 B) |
| 各专家 Agent 的**输入/输出产物** | A 输出的候选器件列表(归一化参数)、B 输出的推荐清单 |
| **Schema 校验**通过的规划 JSON | 校验层确认合法的那份 |
| 仲裁中间结果 | "B 推荐与 C 测试方案矛盾"记录 |

存放:Redis,key = `task_id`,TTL = 任务时长 + 缓冲,聚合完清理。

---

## 生命周期(一条会生长的记录)

```
① query 进来,LeadAgent 规划完成 → 只有 DAG 规划(初始化输入)
② 调度执行中 → 节点状态逐个翻转,专家 Agent 输出持续写回
③ 仲裁聚合 → 矛盾与修正结论写入
④ 任务结束 → 整体清理
```


## 口播版(约 40 秒)

> 工作记忆是 Multi-Agent 执行的任务级状态,放 Redis,key 是 task_id,带任务时长的 TTL。query 进来,LeadAgent 拆出 DAG 和节点状态,这是初始内容;执行中节点状态翻转、每个专家 Agent 的输出写回;仲裁层的矛盾记录也写进去;聚合完整体清理。
> 它存在的意义是让专家 Agent 无状态:重试只重跑失败节点、无依赖节点并行、实例挂了换一个从状态里接手、任务中断能断点续跑——状态全部上移到底座,这正是解决"规划执行强耦合、单点故障"的手段。
> 它和会话记忆的分工:工作记忆是秒到分钟、任务级、给 Agent 用;会话记忆是分钟到天、线程级、给回答生成用。工作记忆初始化时就地取材,读当前线程的摘要和锚点。
