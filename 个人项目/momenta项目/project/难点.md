# 项目难点复盘（"最难的问题"专用叙事）

这类问题（"项目里遇到最难的一个问题是什么，怎么解决的"）面试中几乎必问，且通常只问一次、追问会很深，需要脱稿讲出完整的"转折弧线"，不能照本宣科。这里准备两个候选叙事，二选一使用，视面试官前面聊的方向（更偏 RAG 还是更偏 Multi-Agent 架构）临场选择。

**候选地图**：
- 候选1（Multi-Agent）：失败节点的重规划范围——整体重来 vs 确定性分类 + 局部子图补丁
- 候选2（多模态 RAG）：ColQwen2 + 多模态小模型翻译层——检索定位 与 内容理解 为什么要拆成两个问题

两个叙事的共同结构：**朴素方案 → 具体代价 → 转折认知 → 落地机制 → 量化结果 → 一句话点出"为什么难"**。照这个骨架讲，才有"想清楚了"的说服力，不是背答案。

---

## 候选1：Multi-Agent——失败节点要不要重规划、重规划多大范围

**标准答案**（口播约 90~100 秒，可视反应掐到 70 秒）：

> 最难的问题不是某个具体算法，是 Multi-Agent 执行失败之后，"要不要重新规划、重新规划多大范围"这件事，比听起来复杂得多。
>
> 最直觉的做法是：DAG 里任何一个节点失败，就整体打回去让 LeadAgent 重新规划一遍。我们最初就是这么设计的，但压测和实际跑下来，发现有三个问题。第一是浪费：一个任务往往只有一个节点出错，其余节点早就成功产出了，整体重规划等于把已经算完的结果全部推倒重来。第二个问题更隐蔽，也更危险：让 LLM 重新规划整个任务，它很可能顺手"优化"了原本运行正常的分支，一次局部失败反而引入了一次全局的不稳定，这比"没修好"更糟——它把好的地方也改坏了。第三是可能不收敛：像网络抖动、限流这类瞬时性错误，根本不需要重新规划，原地重试就能过，但如果不加区分地一律触发重规划，同类瞬时错误反复出现时，每次都要重新出一版计划，等于在烧预算做无意义的重复劳动，而且每次新计划长得都差不多，容易陷在原地打转出不来。
>
> 想清楚这件事之后，我们把"要不要重规划"从一次临时的 LLM 判断，改成一套确定性的分类策略：先看失败原因属于哪一类，每一类对应固定的处置方式，不再交给 LLM 临场决定。网络错误、限流、偶发超时——原节点直接重试，不触发重规划；节点正常跑完但没找到可行结果（abstained）——判断是否存在替代检索路径或者能放宽约束，而不是无脑重来；上游没有产出、真正阻塞了下游——才从最初失效的那个节点重新规划；仲裁层发现跨节点事实冲突——只替换冲突的候选或重跑相关分支；缺用户关键信息——不重规划，直接向用户澄清；预算或时间不够——也不重规划，诚实返回部分结果。这一步的关键洞察是：重规划不是一个"失败了就兜底触发"的动作，而是要先分类失败原因，再决定动不动、动多大范围。
>
> 即便真的要重规划，我们也不让 LeadAgent 从头理解整个请求，只把失败原因和已有的产物喂给它，让它输出一个"计划补丁"——只重新生成受影响的局部子图，这个子图照样要过完整的四层校验，不能绕过。同时为了防止真的陷入死循环，设了硬上限：单任务最多重规划两次，新计划不能和上一次完全相同，至少要在工具、约束、执行路径里改变一项，并且全程卡在 token 和端到端超时的预算线内——真收敛不了就诚实止损，返回部分结果，不做无限重试。
>
> 这一套走通之后，"失败分支局部恢复"才从简历上的一句话变成真正能跑的能力——这也是复杂任务平均耗时从 60 秒降到 35 秒里很关键的一部分贡献：省下来的不是正常路径的时间，是原来"一出错就全部重来"浪费掉的那部分时间。
>
> 这道题真正难的地方，是它没有唯一正确答案——正确性、成本、收敛性这三个目标互相牵制，不能只优化其中一个，得靠一套分类清楚的确定性策略把它们同时兼顾住。

**要点**：
- 弧线结构：朴素做法（整体重规划）→ 三个具体代价（浪费 / 引入新错误 / 不收敛）→ 洞察（先分类失败原因，再决定处置策略）→ 落地机制（局部子图补丁 + 四层校验 + 重规划上限）→ 量化收尾（60s→35s 的关键贡献之一）
- "浪费"和"引入新错误"要分开讲，后者更少人会想到——不是"没修好"，是"把好的地方也改坏了"
- 一定要点出重规划上限（2 次、不能重复计划、预算内）——面试官大概率追问"如果一直失败怎么办"
- 收尾一句"三个目标互相牵制，没有唯一答案"直接回答了"为什么难"

**易错点**：
- 别讲成"我们设计了重规划机制"的单纯介绍——重点是"朴素方案为什么不行"这个转折，少了这段就没有"最难"的味道
- 追问"具体怎么判断走哪条处置路径"，如实说是确定性策略/规则判断，不要说成"让 LLM 自己判断"——这会自相矛盾
- 别漏"局部子图仍要过四层校验"——否则听起来像给补丁开了绿色通道

## 候选2：多模态 RAG——ColQwen2 + 多模态小模型翻译层

**标准答案**（口播约 100~110 秒，可视反应掐到 75 秒）：

> 最难的问题是硬件工程师查的 Datasheet 里，效率曲线、波形图这类图表信息——文字层里根本没有，图注只有个标题，没有数据点、趋势、拐点。传统文本 RAG 在这类问题上准确率只有 35%，几乎等于答不出来。这个问题最终是分两步想清楚的，每一步都推翻了一个看起来更简单的方案。
>
> 第一步是"怎么把图表内容检索出来"。最直接的想法是 OCR——把图表转成文字，当成普通文本走原来的 RAG 链路，改动最小。但很快发现这条路走不通：OCR 只能识别印刷体文字，曲线图上根本没有印着"3A 负载下效率 87%"这行字，这个数字是要看懂 X 轴是电流、Y 轴是效率、曲线在 3A 位置对应的高度，推理读出来的——OCR 结构上就不具备这种能力，做出来的东西是空的。另一个直觉是反过来，查询时直接把整页图像扔给多模态大模型去理解、回答，但库里是万级文档，不可能对每一页都跑一次这么贵的推理，也没法一开始就知道该看哪一页。
>
> 真正的转折点是想清楚：这其实是两件事，不能用一个模型糊在一起解决——"从万级页面里定位到答案在哪一个具体区域"是一个检索问题，"看懂这个区域画的是什么"才是一个理解问题，前者要快、要能撑住全量规模，后者可以慢、可以贵，但只能用在小范围。这个认知直接决定了架构：检索阶段用 ColQwen2 把每一页编码成 Patch 级的多向量，不压缩成一个向量，保留页面的空间信息；检索时先用 ANN 粗排从万页里快速捞出候选，再用 MaxSim——每个 query token 单独去页面里找它自己最匹配的 Patch，取最大值而不是整页平均——平均会把真正的答案区域和大片空白、图例这些无关区域混在一起拉低分数，取最大值才能精确定位到"这一页里最相关的那一小块"，而不是笼统地给整页打分。
>
> 第二个转折点是定位到答案区域之后，"谁来把它变成答案"。当时也考虑过让多模态模型直接根据这个区域生成最终答案，但很快意识到这样做会让整个系统的回答质量被"哪个模型同时支持视觉又能力最强"这个交集卡死——而且这个交集通常比纯文本最强模型弱。所以最后的方案是把"翻译"和"回答"彻底分开：多模态小模型只做一件很窄的事——把裁剪出来的这一小块区域描述成一句文字，比如"在3A负载下效率约为87%"，不负责任何推理和最终表达；这段文字和文本路召回的原文一起，交给能力最强的纯文本主力 LLM 去生成真正的回答。这样主力 LLM 的能力上限完全不受视觉模型拖累，而多模态模型也只需要做好一件简单、可控、便宜的事。
>
> 这一整套走通之后，图表类问题准确率从 35% 提到了 73%，而且我们后来做消融验证过：真正带来这次跃升的不是"加了视觉能力"本身，而是 MaxSim 精确定位到答案区域这一步——早期只加视觉检索但不做精排的版本，提升非常有限，因为送去翻译的区域不准，内容被稀释了。
>
> 这道题难的地方在于，它不是一开始就想到"用 ColQwen2 加一个翻译层"这个答案的，而是先要想清楚"检索定位"和"内容理解"是两个不同性质的问题、不能用同一个模型或同一次调用解决，答案才自然浮现出来。

**要点**：
- 双转折结构：转折一（OCR/整页多模态 → 检索与理解要拆成两个问题，前者用 ColQwen2+Patch 向量撑全量规模）→ 转折二（定位到区域后，翻译和回答也要拆开，不能让多模态模型直接给最终答案）
- 每个转折都要先讲"最初想的更简单的方案"再讲"为什么行不通"，这是"惊艳感"的来源，不能直接跳到最终方案
- MaxSim 的"取最大值不用平均"要讲透——这是第一个转折落地的具体机制
- "多模态模型只翻译、不回答"要讲出动机——不让主力 LLM 的能力被视觉模型的能力上限卡住，这是第二个转折的核心
- 收尾用消融数据反证：提升的关键功臣是精确定位（MaxSim），不是"有没有视觉能力"——证明不是拍脑袋出方案，是真的验证过

**易错点**：
- 别把两次转折压缩成一次讲——两次"最初想简单了"的失败尝试才是这题的分量所在
- 被追问"OCR为什么不行"要给具体例子（效率曲线数值是推理出来的，不是印刷体文字），不要只说"OCR有损"这种抽象说法
- 别漏掉消融验证的收尾——这是把"真做过"和"编的好故事"区分开的关键证据

## 临场选择建议

- 如果面试官前面对 **系统架构/工程判断力** 更感兴趣（问过 DAG、状态机、编排层），选候选1。
- 如果面试官前面对 **算法/检索细节** 更感兴趣（问过向量、embedding、排序），选候选2。
- 两个都被追问到时，讲完一个可以补一句"另外一个亮点上也有一个类似量级的坑，要展开吗"，主动递话头，显得心里有底、不是只准备了一个。
