# 知识库检索

## 三路并行（不做路由，全跑）

| 路 | 召回什么 | 技术 |
|---|---|---|
| BM25 | 型号精确匹配（"TPS54331"差一个字是另一颗芯片） | PG tsvector |
| 文本向量 | 语义段落（规格描述、工作条件） | BGE + pgvector |
| 视觉向量 | 图表曲线（文字层里根本没有数据点） | ColQwen2 + pgvector |

为什么不路由：路由判断需要一次 LLM 调用；硬件问题经常同时涉及文字和图表；路由判错代价是整条路漏掉。

---

## 视觉路内部：两阶段精排

```
query → ColQwen2 编码
          │
        ANN 粗排（HNSW）
        万页里快速捞出候选 top-50
          │
        MaxSim 精排
        每页有 N 个 Patch 向量
        取 query 与所有 Patch 相似度的最大值作为页面得分
        → 找到"这页最相关的区域"，不是整页平均
          │
        top-k 页（带最高分 Patch 坐标）
```

MaxSim 的意义：平均分会把无关区域的低分稀释答案区域；MaxSim 只看最相关的那个 Patch，天然完成答案定位。

不加 Reranker：MaxSim 本身已是精排，再叠一层收益边际递减。

---

## 降级判断：在融合前

```
视觉路 MaxSim 最高分
  ├─ 高于阈值 → 三路正常融合
  └─ 低于阈值 → 视觉路降权，退化为文本两路融合
```

在融合前判，不是融合后补救。MaxSim 分是视觉路最直接的置信度信号。

---

## RRF 融合

三路分数量纲不同（TF-IDF / 余弦 / MaxSim），不能直接加权。

RRF 只用排名：`score = Σ 1/(60 + rank_i)`，三路都靠前的候选自然胜出，量纲问题消失。

---

## 图像翻译层：多模态模型只做"图像→文字"

```
视觉候选（Patch 区域裁剪图）
        │
   多模态小模型（只做一件事：描述这个区域的内容）
        │
   文字描述（"在3A负载下效率约为87%"）
        │
        └─ 和文本候选合并
                │
          主力纯文本 LLM 生成最终答案
```

多模态模型不负责回答，只负责把图像翻译成文字。主力 LLM 永远是纯文本的，不受视觉能力约束，可以用最强的文本模型。

降级时直接跳过翻译层，只走文本两路，一个开关，干净。

---

## 完整链路

```
用户 query
    │
  三路并行检索
    │
  视觉 MaxSim 分 < 阈值？→ 是：视觉降权，两路融合
                          → 否：三路 RRF 融合
    │
  视觉候选 → 多模态小模型翻译 → 文字描述
  文本候选 → 直接取文字
    │
  合并 context → 主力纯文本 LLM → 答案
```

---

## 一句点睛

从跳过 OCR 开始，ColQwen2 直接吃图像；ANN 粗排压候选量；MaxSim 精排定位答案 Patch；裁剪区域送多模态翻译层输出文字；最终主力 LLM 只看文字。**视觉信息从进库到翻译全程保真，翻译层之后和文本信息对齐**。
