# Skill & MCP · 叙事版

## 一句话定位

**Skill 解决"怎么做"（流程固化），MCP 解决"从哪取数"（系统接入）。**

---

## 痛点

**流程侧：** LLM 即兴推理选型步骤，同样的请求每次跑出的流程可能不一样；部门强制要求的必查项（如国产替代验证）可能被跳过；工程师积累的选型经验散落在 prompt 里，无法沉淀复用。

**接入侧：** 存量系统（项目管理、物料查询）硬编码在 Agent 里，接一个新系统要改代码重新部署；三个子 Agent 各自重复实现对同一系统的调用。

---

## 方案

### Skill：把 SOP 固化成确定性执行单元

```
用户请求 → 匹配 Skill → 固定步骤执行
                │
         步骤示例（器件选型 Skill）：
           1. 参数归一化          ← 确定性代码
           2. 结构化库查询        ← MCP 工具调用
           3. 候选筛选            ← LLM 判断（只在这里介入）
           4. 国产替代验证        ← MCP 工具调用（强制步骤，代码保证）
           5. 库存/交期查询       ← MCP 工具调用
           6. 输出推荐报告        ← LLM 生成
```

- 步骤顺序固定，必查项由代码保证，不靠 LLM 自觉
- LLM 只出现在需要语义判断的节点，其余是确定性逻辑
- 部门经验编码进步骤和判断规则，新人和老工程师用，流程质量一样
- 沉淀 **10+ 工作流**的 Skill

### MCP：存量服务标准化接入

```
存量系统 → 封装成 MCP Server → 注册进来
                │
         Agent 启动时动态发现工具列表
                │
         LeadAgent 规划时按需分配
```

- 新增系统只写一个 MCP Server，Agent 代码不动
- 三个子 Agent 共享同一套工具，不重复实现
- Agent 动态发现可用工具，LeadAgent 规划时从清单里按需分配

---

## 与 Multi-Agent 架构的咬合（面试时主动说）

> Skill 就是专家 Agent 内部流程的具体实现，LeadAgent 只看它的 produces/consumes，不感知内部有几步；MCP 工具是 Skill 内部取数据的通道。三层分工：LeadAgent 管编排，Skill 管领域流程，MCP 管系统接入。

---

## 简历句

> 针对 Agent 即兴推理流程不稳定、存量系统硬编码接入难维护的问题，将硬件研发 SOP 抽象为 Skill 执行单元：步骤固定、必查项由代码保证、LLM 只在判断节点介入，沉淀 10+ 工作流；同时将项目管理、物料查询等存量服务封装为 MCP Server，Agent 动态发现与调用，新增系统无需改动 Agent 代码。

---

## 口播版（约 40 秒）

> 这个亮点解决两个问题。第一个是流程不稳定：之前硬件选型这类任务全靠 LLM 即兴推理步骤，同样的请求每次跑的流程可能不一样，部门强制要求的国产替代验证这类必查项也可能被跳过。我们的方案是把 SOP 固化成 Skill 执行单元——步骤顺序是确定性的，必查项由代码保证，LLM 只出现在需要语义判断的节点，比如候选筛选和生成报告，最终沉淀了 10 多个工作流的 Skill。
>
> 第二个是系统接入：存量系统之前硬编码在 Agent 里，接一个新系统就要改代码重新部署。我们把这些服务封装成 MCP Server，Agent 启动时动态发现可用工具，LeadAgent 规划时按需分配，新增系统只写一个 MCP Server，三个子 Agent 共享，不重复实现。
