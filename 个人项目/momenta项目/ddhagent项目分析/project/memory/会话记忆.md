# 会话记忆(短期记忆

## 一句话定义

短期记忆的单元不是"会话",而是**话题线程(topic thread)**。核心机制是**话题关联识别**:判定一条新消息归属哪个线程(含"新建线程"这个选项)。

为什么:飞书私聊是永不结束的单流、群聊是多用户多话题交错,都没有网页版那种物理多会话;但两条线本质相同——都是无限消息流,群的差异只是多一个 user 维度。一套机制,两个频道复用。

--
## 一、话题关联识别:完整流程(背诵版)

```
新消息到达
│
├─ 0. 强信号预检(免匹配,零成本零误判)
│     引用回复 → 直接继承被引用消息的 thread_id
│     显式指令("换个问题")→ 直接新开线程
│
├─ 1. 与活跃线程匹配(数量少,热上下文在 Redis,embedding 相似度)
│     ├─ 高于高阈值 → 并入追加
│     ├─ 低于低阈值 → 未命中,转 2
│     └─ 落在模糊带 → 小模型 LLM 裁决:继续 / 新话题 / 引用前文
│
├─ 2. 查软关闭池(距最后一条消息超 30 分钟,摘要冻结、锚点保留,可复活)
│     ├─ 先锚点倒排精确命中(型号归一化后查倒排索引)→ 复活
│     ├─ 提取不出实体(纯指代"刚才那个")→ 最近软关闭的线程优先
│     └─ 兜底:embedding 相似度 → 命中复活
│
└─ 3. 全部未命中 → 新建线程
```

一句话背:"先强信号,再热线程向量,再去软关闭池锚点优先、向量兜底,中了复活,不然新开。"

## 口播版(约 40 秒)

> 私聊看起来是一个永不结束的会话,但短期记忆的单元不应该是"会话",而是话题线程。所以我们的做法是判定每条新消息归属哪个线程,而不是切会话本身。
> 判定走三层信号:最强的是飞书自带的引用回复,引用哪条消息就继承哪条的线程;其次是时间间隔和显式指令;最后才是语义相似度——高合并、低新建,模糊带交给小模型裁决。
> 线程生命周期是活跃、软关闭、复活、归档:半小时没消息就软关闭,摘要冻结但保留;用户过后说"继续刚才那个芯片",还能靠锚点实体复活;超过一天才归档,摘要异步进长期记忆。
> 核心取舍是宁可多切、不可误并:误切丢上下文能靠复活兜底,误并带来噪音。RAG 场景里噪音比缺失更危险。
