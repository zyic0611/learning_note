## 意图路由

本质是在网关层对用户的行为进行分类，将**纯展示变换** 从沉重的取数链路中剥离出来。

**识别逻辑**：系统通过轻量级的规则引擎或小模型，扫描用户的 `new_question`。如果命中**可视化词汇库（Visualization Lexicon）**（如：“饼图”、“柱状图”、“折线图”、“降序排一下”、“只看前十名”等），且不包含新的过滤条件（如“加个时间范围”），则判定用户的意图仅仅是“换个姿势看现有的数据”。

**路由分发**：在 LangGraph 的图中，这体现为一个**条件边 (Conditional Edge)** 分支。意图路由判定为“纯展示”后，直接跳过核心的 `agent ↔ tools`（SQL 生成节点），将图的状态导向一个极其轻量级的专属节点：`generate_chart_config`（专门输出 Echarts 或前端组件 JSON 配置的节点）。

## 缓存感知路由

意图路由能跑通的先决条件，是系统知道“现在有米下锅”。这就高度依赖记忆产物 

**状态校验**：快路径的触发条件极其严苛。除了 `related=True` 和命中可视化词汇，系统必须去 `AgentState` 中检查一个关键指针，例如 `has_cached_rows=True` 或判断 `len(state["queried_data"]) > 0` 也就是确实有符合的记忆产物

**数据复用**：当流程进入 `generate_chart_config` 节点时，LLM 不需要看底层数据库表结构了。它的 Prompt 直接拼接 `AgentState.queried_data`（即上一轮成功查出的几十行 JSON 结果）和用户的最新需求（“画个饼图”），迅速吐出一个图表配置，前端直接拿着旧数据和新配置重新渲染。
