在一个高鲁棒性的工业级 Agent `app.py` 编排中，它们的执行顺序是有严格讲究的，通常遵循“先低成本，后高成本”的过滤原则。完整的流转关系如下：

1. **用户发起请求 (START)**。
2. **话题关联判定 (Topic Segmentation)**：首先判断是不是新话题，决定是否重置记忆。
3. **指代消解**：确定与上文有关了 就看有没有指代的东西 能替换成历史对话里的东西
4. **规则口径澄清 (Guardrail)**：过一遍 规则口径澄清 看有没有业务模糊的词 或者风险的词。如果触发正则规则，直接短路路由到 口径澄清。
5. **领域分类识别 (Classify Domain)**：如果规则引擎没拦截，再调用一次 LLM 判断是否属于环卫业务范围。如果超纲，再次短路路由到 口径澄清。
6. **核心执行层 (Agent Loop)**：只有连续通过了上述所有防线的请求，才被允许进入核心的 Tool Calling 和 ReAct 思考环节。
