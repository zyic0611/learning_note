Topic Segmentation 是整个会话管理（Session Management）的第一道防线，甚至比口径澄清还要靠前。

大语言模型本质上是无状态的，它之所以能“记住”上下文，全靠我们在请求时将历史 `messages` 喂给它。但这带来了一个架构矛盾：如果用户突然切换了话题（例如上一秒在查“静安区清运车状态”，下一秒问“系统怎么修改密码”），强行带着上一轮的 `summary`摘要 和数据库查询结果（产物记忆）去回答新问题，不仅会造成严重的上下文污染 ，还会白白浪费大量的 Token 成本。

因此，我们需要一个网关来决定：是**继承**当前状态，还是**重置**状态。以下是这套机制的底层原理与工程博弈。

## 运转机制 如何区分

在判定 话题是否关联的 设计中  输入参数为 当前问题、上一轮问题、摘要（长期记忆）。这是一个极其经典的三角判定模型，缺一不可：

- **`new_question` (当前输入)**：用户的最新意图。如果是“那外包车队呢？”，它包含强烈的代词或省略语境。
- **`prev_question` (上一轮问题)**：提供**指代消解**的锚点。LLM 必须通过对比“查直营车队状态”和“那外包车队呢？”，才能判定后者是紧密相连的追问。也就是主要分析追问
- **`summary` (全局情节摘要)**：防止局部偏离导致的话题断裂。有时候用户的追问跨度稍大，但仍在同一个业务办理流程（如“工单派发”）内，`summary` 能提供宏观的业务边界证明。

这个节点通常由一个**轻量级的 LLM 调用**来完成，它只输出 `True`（话题延续）或 `False`（新话题）。

## 问题 误判引发的断链

在实际业务中，最致命的工程事故往往不是大模型回答错误，而是**上下文断链 (Context Break)**。

当你把多轮对话交由 `is_topic_related` 判定时，系统面临两种错误类型：

1. **假阳性 (误判为相关)**：用户确实换了话题，但系统没识别出来。
   - *代价*：带入了无用的历史数据，增加了少量 Token 消耗，LLM 可能会有一点短暂的困惑，但通常能依靠自身的注意力机制忽略旧信息，**业务不会崩溃**。
1. **假阴性 (误判为无关)**：用户其实是在追问，但系统判定为新话题。
   - *代价*：触发 重置会话。当前 AgentState 中的 `messages` 和 `summary` 被彻底清空。当用户输入“占比是多少？”或“帮我导出刚才的数据”时，Agent 会变成一张白纸，回复“请问您要导出什么数据？”，**导致多轮交互逻辑直接死锁，用户体验极差**。



## 架构哲学 保守设计

保守策略：LLM 解析失败 → 默认 `related=True`  是针对上述“假阴性”灾难的标准防御手段。

在工程实现中，调用 LLM 进行 Boolean 判定时，可能会遇到网络超时、JSON 解析失败或模型输出模棱两可的情况。在遇到这些异常状态（Exception）时，系统**绝对不能**默认清空记忆。

默认返回 `True` 的本质是：**宁可承担上下文冗余和 Token 浪费的代价（高容错），也绝不主动切断用户的业务逻辑链（低破坏）**。这在分布式系统架构中，类似于降级策略 ，优先保全核心业务流程的连贯性。

## 话题判断 演进

在后续的优化中（尤其是面对高并发场景），完全依赖 LLM 进行每一次的话题判定会带来显著的延迟（Latency）。业界通常会采用分层判断的策略，

### 纯 LLM 推理判定 

**实现** ：Prompt(当前+历史+摘要 三角关系) -> Boolean 

**延迟和性能损耗：**最高（依赖完整 LLM 生成周期，通常 >500ms）

**准确率与Context break风险**：语义理解最深，极少出现“假阴性”，但容易发生格式解析异常

### 向量相似度

**实现**：计算 `new_question` 与历史对话的 Cosine Similarity

**延迟和性能损耗**：极低（毫秒级），依赖本地化 Embedding 模型

**准确率与Context break风险**：字面相似度高则准，但对于“代词追问”（如“那另一个呢？”）容易触发误判断链

### 混合网关 (Heuristic规则 + LLM)

**实现**：优先匹配强正则/规则，比如判断 然后呢 还有呢 他是什么 这些基本都是代词规则 肯定和上文有关，再算向量，也就是如果规则判断不了 就向量和历史对话匹配 如果判定为相关 最好 如果无关，最后就 LLM 兜底

**延迟和性能损耗**：中等（大量请求在规则层和向量层被低成本拦截）

**准确率与Context break风险**：极高，兼顾了规则的确定性和 LLM 的语义推理能力
