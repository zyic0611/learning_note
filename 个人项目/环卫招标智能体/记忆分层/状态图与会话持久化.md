## Checkpoint

全量状态快照（不止于 Messages） 

在 LangGraph 中，**Checkpoint** 的本质是一个伴随图节点流转的“游戏存档”。

**全量保存机制**：当图执行到一个断点（例如等待用户输入，或者节点执行完毕）时，Checkpointer 序列化并保存的是整份 **AgentState** 字典。这意味着除了对话历史，诸如 `in_domain`（领域分类标识）、`clarify_message`（澄清话术）以及 `summary`（情节摘要）等所有业务字段都会被完整冻结并持久化。

**Reducers（聚合器）的作用**：当新的消息产生时，图框架不会直接用新消息覆盖旧列表，而是调用这个 reducer 将新消息**追加**或**合并**到现有快照的 `messages` 列表中。

**业务价值**：在你的 `classify_domain → clarify_scope` **意图分识别与边界澄清**  流程中，如果判定用户输入超纲，系统会将 `in_domain = False` 写入 State。在下一轮对话恢复时，Agent 能够直接从快照中读取到这个布尔值，并维持在 `clarify_scope` 节点的逻辑中，而不会发生状态重置或重新走一遍分类逻辑。







## Session ID

**session_id** 是唤醒特定 Checkpoint 快照的唯一凭证，也是实现 Agent 隔离的核心。

**隔离原理**：大模型 API 本身是无状态的。当多个请求同时打到后端时，系统依靠传递给 `app.invoke()` 的 `config={"configurable": {"thread_id": session_id}}` 来寻址对应的内存块或数据库行。



## 持久化演进

目前的 **MemorySaver** 是基于 Python 字典实现的内存级存储。它的读写极其轻量，但随着服务重启、进程崩溃或需要多实例部署时，数据会瞬间清空。为了推进到 高级阶段，你必须将存储层替换为持久化数据库。

**MemorySaver**  

​	进程内存（RAM），重启即丢失 

​	本地开发调试、单测运行 

​	无需网络 IO，零延迟，不支持多实例部署。

**SqliteSaver** 

​	本地磁盘文件（`.db`），持久化

​	概念验证（PoC）、单机轻量级部署

​	依赖文件系统 IO，支持基础 SQL 查询，多进程写入时容易锁表。

**RedisSaver**

​	基于内存的分布式键值对持久化

​	工业级生产环境、高并发集群部署

​	极高的读写吞吐量，天然支持分布式锁和 TTL 过期策略。
