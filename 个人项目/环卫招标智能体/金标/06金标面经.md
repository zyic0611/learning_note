金标实战

在我的 NL2SQL Agent 项目中，我们维护了一套 Golden Set，用于持续评估整个 NL2SQL Pipeline 的效果，而不是仅依赖人工体验。

Golden Set 并不是只有 SQL，而是覆盖了多个阶段：
首先是 Query Understanding 金标，验证意图识别和槽位抽取；
其次是 Schema Linking 金标，断言应该召回的表和字段；
然后是 SQL Generation 金标，通过 SQL AST 或关键 SQL 片段断言验证生成结果；
另外还有 多轮对话金标，验证 AgentState 中 Topic 和 Slot 的继承是否正确。

对于开发阶段，我们还维护了一套 Seed SQL Set，既可以作为 Mock 数据驱动 Guardrail 和执行链路测试，也可以作为 RAG 检索到的 Few-shot 示例增强 Prompt。

线上错误案例会先进入待审核集合，人工确认后再晋升为新的 Golden Set，使整个测试集随着业务不断进行演进，
并作为回归测试集在每次 Prompt、Schema 或模型更新后自动执行，确保系统能力不会出现回退。
