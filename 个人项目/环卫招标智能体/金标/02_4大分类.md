## Question -> Sql 金标

也就是 Golden Set

一般是 YAML文件  内容是

- id： 
- question ：自然语言提问
- excepted_sql： 期望的sql语句

但是一般不会要求生成的sql完全一致  **所以一般不会做字符串比较 而是做AST断言比对**。

用处是作为标准答案 测试llm生成的sql和标准答案的差距。 可以测试整个pipeline

## Schema Linking 金标

expected_tables、expected_columns 就是这个。

一般是YAML文件 内容是

- question：自然语言提问
- expected_tables ：期望召回的表
- expected_columns：期望召回的列

然后测试 schema linking 是不是召回了这些

这里就会涉及到两个参数： Recall率 Precision率

**这种比SQL更准 因为大部分时候 并不是SQL错误 而是模式链接的错误**

## SQL片段断言

一般是YAML文件 内容是

- sql_must_contain:
  - projectStatus 项目状态
  - Deleted
  - Group by

一般不会用整条SQL 因为SQL写法非常多 顺序也不一样。

企业一般都是使用AST断言 或者用 Must Contain规则 用YAML文件规则。 不包含这些 就失败。比字符串稳定。

是用于验证生成的SQL是否包含必须出现的关键SQL片段。

## SQL Seed 金标sql模版

一般是yaml文件 内容是

- seed_id:
- sql:sql语句

### 用途1 Mock：

在开发阶段 LLM太昂贵 则可以不用LLM 直接走

问题->Seed Sql ->Guard ->Execute 链路

只测试Guard Policy Executor 不用花费Token

### 用途2 Few-shot

例如RAG中检索某个问题的时候 找到某条金标sql 注入提示词 参考下面的案例生成SQL 会提升准确率

### 总结：

seed sql 更像是知识库 不是答案 是作为示范 这是和golden sql的最大区别。 kennel和golden set长得一模一样 但是还是会分两个 因为用途不同 golden主要是评测  seed主要是用于生成。
