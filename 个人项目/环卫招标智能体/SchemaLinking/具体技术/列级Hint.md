在 NL2SQL架构中，它是引导大语言模型 (LLM) 准确理解业务字段语义的核心手段

在构建基于 LLM 的数据库问答 Agent 时，一个普遍的痛点是 **Schema Linking**失败的痛点。如果仅将物理表的建表语句（`CREATE TABLE`）喂给大模型，模型极易产生**幻觉 (Hallucination)**，因为它无法猜测业务层面的隐式逻辑

在这种场景下，列级 Hint 是指**在 Prompt 中为特定列补充的业务语义、枚举值映射或格式约束**。它是将“物理数据模型”翻译为“业务逻辑模型”的桥梁。

简单说 就是给每一列的字段做一个解释 通过注入列级 Hint，基于大模型的 Agent 能够有效避免诸如 `WHERE status = '已完成'` 这种导致语法错误或查无数据的低级失误。

## 常见的列级Hint类型

### 枚举值映射  

解决模型错误地使用中文字符串去匹配整型状态码

 比如0映射 未完成 1映射已完成

### 度量单位换算

解决 金额、距离等数值单位在数据库与用户认知间存在差异

比如 数据库存储单位为“分”，生成 SQL 时必须 `/ 100` 转化为“元”

### 时间格式约束

模型使用了错误的日期函数，导致无法命中**覆盖索引**

必须使用 `>=` 和 `<` 进行范围查询，严禁使用 `MONTH()` 函数包裹此列

### 业务隐式逻辑

专用名词或缩写无法被通用大模型直接理解

任何查询必须附加 `is_deleted = 0` 的过滤条件以排除逻辑删除数据
