为了服务set的 因为set有序。

IntegerSet 整数集合。 为了节约内存。

## 条件

创建redis的set集合 如果里面全都是整数 并且数量不多 默认<512 redis就不会用Dict存 只会用intset。



## 内存结构

```c
typedef struct intset {
    uint32_t encoding; // 编码方式（决定每个元素占几个字节：16位、32位、64位）
    uint32_t length;   // 集合包含的元素数量
    int8_t contents[]; // 柔性数组，真正存数据的地方
} intset;
```

虽然contents是int8的数据类型 但是会根据encoding的数据类型 进行强制类型转换

## 核心特性

数组里绝对有序  必须是从小到大

所以查找元素用的是二分查找 cpu二分查找几百个元素 非常快 但是却剩下了很多哈希表指针。 牺牲cpu换内存空间。



## 升级机制

假设建立一个Set 存1 ， 2， 3 用INT16就行了 此时encoding是int16

此时插入了一个6553500 需要int32 此时就触发升级。

1.重新分配内存

先根据新元素的类型 计算出需要的内存空间

2.从后往前搬迁数据

这样可以防止旧数据被覆盖 从后往前 转换格式后迁移

3.安置新元素

由于新元素触发升级 所以要么极大 要么极小 肯定在数组开头或者结尾

4.更新头部信息

修改encoding length+1

## 降级

Redis 的 Intset **只支持升级，不支持降级**。一方面是防止有反复处于临界值的元素频繁进出，导致不断进行极其耗费 CPU 的内存重分配；另一方面，既然你的业务曾经放入过大整数，说明大概率以后还会放，维持现状是性价比最高的做法。
