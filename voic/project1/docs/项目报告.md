# 基于 MFCC 与 EMD 的相似歌曲检索系统

## 摘要

本项目实现了一个基于音乐内容的相似歌曲检索系统。系统不依赖歌曲标题、艺术家信息或用户行为，而是直接接收 WAV、MP3 等音频文件，从中提取梅尔频率倒谱系数（MFCC）。系统截取歌曲中间 30 秒，将其表示为 3000 个 20 维短时特征向量；随后通过 k-means 向量量化将这些特征压缩为 16 个聚类，并使用每个聚类的权重、均值向量与协方差矩阵形成歌曲指纹。聚类之间采用对称 Kullback-Leibler 散度作为代价，歌曲指纹之间采用 Earth Mover's Distance（EMD）求最优运输距离。对小规模曲库使用线性扫描完成排序。

为解决版权与实验可复现问题，项目生成了 48 首合成演示歌曲，包含 6 个音色家族，并实现可播放查询与结果片段的 Web 页面。每首歌曲轮流作查询的评估结果为：Top-1 Accuracy 79.2%、Precision@5 67.5%、Recall@5 48.2%、mAP 71.8%。实验表明，基础 MFCC 方法能够有效捕捉音色相似性，同时在频谱特征接近的钢琴、电钢琴与木吉他之间存在混淆。项目使用 Docker 封装运行环境，支持 Intel 与 Apple Silicon Mac。

**关键词：** 音乐信息检索；MFCC；k-means；KL 散度；EMD；基于内容检索

## 1. 研究背景

传统音乐搜索通常依赖歌曲标题、艺术家等文本信息；协同过滤推荐依赖用户的播放、收藏或购买记录。当用户只有一段音频，或希望查找“听起来相似”的歌曲时，这两类方法都不能直接利用音乐内容。因此，需要研究基于内容的音乐信息检索（Music Information Retrieval，MIR）。

本项目参考 E. Pampalk 对音乐相似度模型的总结，以及 B. Logan 和 A. Salomon 提出的基于局部频谱特征的音乐相似度方法，选择 MFCC、向量量化和 EMD 组成一套基础、可解释的检索流程。

## 2. 系统目标

1. 直接以音频文件作为查询输入；
2. 使用 MFCC 表示短时音色；
3. 使用 k-means 压缩大量帧特征；
4. 使用高斯分布表示聚类；
5. 使用对称 KL 散度和 EMD 计算歌曲距离；
6. 输出按距离升序排列的相似歌曲；
7. 通过网页试听查询和结果；
8. 提供可量化的实验评估；
9. 通过 Docker 保证跨平台运行。

## 3. 系统设计

### 3.1 总体流程

```text
音频输入
  ↓
解码、单声道化、16 kHz 重采样
  ↓
截取中间 30 秒
  ↓
20 维 MFCC × 3000 帧
  ↓
k-means（k=16）
  ↓
16 个高斯分布（w, μ, Σ）
  ↓
16×16 对称 KL 代价矩阵
  ↓
EMD 运输线性规划
  ↓
全库线性扫描与排序
  ↓
Top-10 + HTML5 音频播放
```

### 3.2 音频预处理

系统统一将输入转换为 16 kHz 单声道浮点波形。标准 WAV 由 Python `wave` 模块直接读取，MP3、FLAC、M4A 等由 ffmpeg 解码。对于长音频，截取中心位置总计 30 秒；不足 30 秒则保留整首。

### 3.3 MFCC 特征

帧长设为 400 个采样点（25 ms），帧移为 160 个采样点（10 ms），使用 512 点 FFT 和 40 个 Mel 滤波器。对 Mel 能量取对数后进行 DCT，保留 c0–c18 共 19 个倒谱系数，再附加一维帧对数能量，形成 20 维特征。

30 秒音频每 10 ms 产生一帧，共 3000 帧，即初始表示包含 60,000 个浮点数。

### 3.4 向量量化与歌曲指纹

使用 k-means++ 初始化和 Lloyd 迭代，将 3000 个 MFCC 向量划分为 16 类。对每个聚类计算：

- 权重 `w_k`：聚类中的帧数；
- 均值 `μ_k ∈ R²⁰`；
- 协方差 `Σ_k ∈ R²⁰ˣ²⁰`。

每类 421 个数，16 类共 6736 个数，与原始 60,000 个数相比压缩约 88.8%。为避免协方差矩阵奇异，在其对角线添加微小正则项。

### 3.5 对称 KL 散度

普通 KL 散度具有方向性。为使歌曲距离满足交换对称性，使用：

```text
D_SKL(P,Q) = [KL(P||Q) + KL(Q||P)] / 2
```

对歌曲 A 的 16 类和歌曲 B 的 16 类两两计算，得到 16×16 运输代价矩阵。

### 3.6 EMD

将两个指纹的归一化聚类权重看作供给与需求，以对称 KL 作为单位搬运成本，求解总成本最小的运输问题。项目使用 `scipy.optimize.linprog` 的 HiGHS 求解器。该数学问题与参考实现通过 R `lpSolve` 求解的运输问题一致，但减少了跨语言依赖。

### 3.7 检索

曲库规模为几十至几百首时，对所有歌曲逐一计算 EMD 并排序即可。该实现算法清晰、结果可复核。查询为库内歌曲时排除自身；上传音频则与全部库内歌曲比较。

## 4. 实现

项目采用 Python 3，主要依赖 NumPy、SciPy 和 ffmpeg。MFCC、k-means、高斯指纹、KL、EMD 分别位于独立模块，Web 服务仅使用 Python 标准库实现，避免引入与核心算法无关的复杂框架。

系统提供：

- 命令行建库、检索和评估；
- Web 下拉查询；
- 外部音频上传查询；
- HTML5 音频播放器；
- 离线评估报告；
- Docker Compose 一键启动；
- 18 项数学自检。

## 5. 实验设计

### 5.1 数据集

由于公开分享商业音乐存在版权问题，项目通过加法合成生成 48 首 40 秒歌曲。数据分为钢琴、电钢琴、木吉他、弦乐、长笛、合成器 6 个家族，每个家族 8 首。

同一家族共享主要谐波结构、包络或噪声特性，但歌曲的调性、速度、和弦进行和旋律随机变化。因此标签表达的是音色类别，而不是文件名规则。检索算法不读取这些标签。

### 5.2 评估协议

采用 leave-one-out 方式：每首歌轮流作为查询，并从候选库排除自己；同家族其余 7 首视为相关结果。48 首共产生 `48×47/2=1128` 个不重复歌曲对距离。

### 5.3 指标

- Top-1 Accuracy：第 1 名是否相关；
- Precision@5：前 5 名中的相关比例；
- Recall@5：7 首相关歌曲中被前 5 名找回的比例；
- mAP：所有查询 Average Precision 的均值。

## 6. 实验结果

| 指标 | 结果 |
|---|---:|
| Top-1 Accuracy | 79.2% |
| Precision@5 | 67.5% |
| Recall@5 | 48.2% |
| mAP | 71.8% |

按家族观察：

- 合成器 Top-1 为 100%，P@5 为 100%；
- 弦乐 Top-1 为 100%，P@5 为 100%；
- 长笛 Top-1 为 100%，P@5 为 95%；
- 木吉他、钢琴、电钢琴出现更多交叉混淆。

合成器具有丰富高频谐波和鼓点噪声，弦乐具有缓慢起音和持续特征，长笛谐波较少，因此它们的 MFCC 分布差异明显。钢琴、电钢琴和木吉他均为较明显的起音—衰减型音色，频谱包络存在重叠，说明仅依赖 MFCC 的系统存在边界。

## 7. 正确性验证

测试覆盖：

1. 30 秒产生 3000 帧；
2. MFCC 为 20 维；
3. 使用 19 个 c0–c18 系数；
4. 截取时长和短音频行为；
5. MFCC 无 NaN/Inf；
6. 对称 KL 自距离为 0；
7. 对称 KL 交换对称；
8. 普通 KL 非对称；
9. 对称 KL 非负；
10. 向量化代价矩阵与定义的双循环实现一致；
11. 代价矩阵转置对称；
12. EMD 自距离为 0；
13. EMD 交换对称；
14. 不同指纹 EMD 大于 0；
15. 权重整体缩放不影响 EMD；
16. 指纹保存与读取一致；
17. `.sig` 每行 421 个值；
18. 其他基础形状与有限值检查。

最终结果为 18 项通过、0 项失败。

## 8. 部署

Docker 镜像包含 Python、NumPy、SciPy 和 ffmpeg。`compose.yaml` 将 `data` 和 `out` 映射到宿主机，便于替换歌曲、保存指纹与评估结果。Dockerfile 不固定架构，可由 Docker Desktop 在 Intel Mac 使用 amd64，在 Apple Silicon Mac 使用 arm64。

启动命令：

```bash
bash docker.sh start
```

访问：`http://localhost:8088`。

## 9. 局限与未来工作

1. MFCC 主要描述音色，对旋律和节奏不敏感；
2. 聚类忽略帧的时间顺序；
3. 固定取中间 30 秒不一定是最有代表性的片段；
4. 合成数据的标签比真实音乐流派更明确；
5. 线性扫描不适合百万级曲库。

未来可加入 chroma、音高轮廓、tempo 或 tempogram；可通过音乐结构分析选择副歌；可在大规模场景采用近似最近邻召回和 EMD 重排序。

## 10. 结论

本项目完整实现了基于 MFCC、向量量化、高斯分布、对称 KL 和 EMD 的内容音乐检索流程，并通过可播放 Web 页面和定量评估验证了其有效性。结果表明，经典 MFCC 方法能够较好地区分具有明显音色差异的歌曲，同时也暴露了单一音色特征在相似乐器之间的局限。系统算法基础、结构清晰、可复现，并通过 Docker 实现跨平台演示，满足学习原理和现场展示的双重目标。
